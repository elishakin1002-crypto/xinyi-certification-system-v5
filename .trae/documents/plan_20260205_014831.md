# 线索生命周期硬锁 + 归类管理实施方案

根据最新的【投喂 Trae｜立即执行】指令，我将对系统进行**不可逆**的规则改造，确保线索“用完即退役”。

## 1. 后端逻辑硬锁 (`context/AppContext.tsx`)

### 修改 `createFollowUpProjectFromLead`

实施**最严格**的阻断策略：

* **规则 A（状态锁）**：若 `lead.status === 'Converted'`，直接抛出错误：“该线索已转化，请前往客户库操作”。

* **规则 B（关联锁）**：查询 `projects` 中是否存在 `contractRef === 'LEAD:{id}'` 的记录。

  * **只要存在**（无论 Active, Completed, Cancelled），一律视为“已消耗”。

  * 直接抛出错误：“该线索已生成过项目，禁止重复使用”。

此修改将从数据逻辑层彻底切断“同一线索生成多个项目”的可能性。

## 2. 前端列表归类与 UI 改造 (`pages/Leads.tsx`)

### A. 默认列表过滤

* 修改 `Leads` 组件的渲染逻辑。

* **默认视图**：仅展示 `Status.New`, `Status.Pending`, `Status.Risk` 等活跃状态。

* **隐藏对象**：默认**不渲染** `Status.Converted` 和 `Status.Lost` 的线索。

* **找回方式**：用户必须通过顶部的“状态筛选器”主动选择“已转化”或“全部”，才能看到这些历史数据。

### B. 卡片行为锁定（UI 退役感）

针对 `Converted` 状态的线索卡片：

* **按钮改造**：将“转项目”按钮替换为灰色的“已转化”标签，且不可点击。

* **编辑禁用**：点击编辑时，禁用关键字段（名称、代码、联系人）的输入框，或直接提示“已归档线索不可编辑关键信息”。

* **视觉降级**：卡片样式可能会做灰度处理或增加“已归档”水印（视现有 UI 风格而定），强化“退役”心理暗示。

## 3. 客户经营闭环引导

* 在阻断操作的提示语中，明确引导用户：“后续合作请在【客户详情页】发起”。

* 确保 `createFollowUpProjectFromLead` 在成功时，正确执行了客户绑定（基于之前的 PDCA 逻辑），保证用户去客户库时能找到对应记录。
