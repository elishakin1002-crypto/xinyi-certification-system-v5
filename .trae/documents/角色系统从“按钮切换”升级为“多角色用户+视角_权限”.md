# 角色切换为什么“看起来没区别”

你说得非常准确：当前系统的“角色切换”本质上只是一个**全局变量 currentRole**，主要用于“提醒过滤”，并没有把角色变成真正的“职责视角/权限边界”。

在现实现状里：
- 角色切换 UI 只是把所有角色列在一个下拉里：[Layout.tsx](file:///Users/jinxiansheng/Downloads/信义认证系统-v5.0-ai综合版%20(1)/components/Layout.tsx#L54-L79)
- 角色的实际效果几乎只体现在“提醒过滤”这一处：`(!r.forRole || r.forRole.includes(currentRole))`：[Layout.tsx](file:///Users/jinxiansheng/Downloads/信义认证系统-v5.0-ai综合版%20(1)/components/Layout.tsx#L30-L33)
- 自动扫描生成提醒时只是给提醒打 `forRole` 标签：[AppContext.tsx](file:///Users/jinxiansheng/Downloads/信义认证系统-v5.0-ai综合版%20(1)/context/AppContext.tsx#L61-L111)
- 侧边栏、路由、页面内容不按角色区分（所有人都看到全部模块）：[Sidebar.tsx](file:///Users/jinxiansheng/Downloads/信义认证系统-v5.0-ai综合版%20(1)/components/Sidebar.tsx)

所以你看到的效果就是：
- 不管你切换到哪个角色，页面几乎不变；
- 只是在“提醒数量/提醒内容”上可能有一点变化；
- 这当然会让人感觉“和没区分角色差不多”。

# 小公司“身兼数职”的正确做法

小公司多岗位并不意味着“不需要角色”，恰恰相反：
- 你需要的是“**一个人拥有多个角色（roles）**”，但在某个时刻只能用一个“**工作视角（activeRole / persona）**”来聚焦。
- 另外，“看什么/默认怎么显示（视角）”和“能不能看（权限）”是两件事。

下面给出 2 套可落地方案（你可以选其一，或二合一）。

## 方案 A：只做“视角”，不做严格权限（最快最贴合小公司）
**核心思想**：角色=工作台视角（focus），不是权限（auth）。
- 角色切换带来明显变化：
  - 默认首页卡片/指标不同（老板看风险与回款，咨询师看任务与到期）
  - 默认筛选不同（例如咨询师默认只看“我负责/我参与”的项目）
  - 侧边栏可“强调/折叠”不同模块（但不强制隐藏）
- 好处：改动小、体验立竿见影、不会“切到别的角色就看不到东西”。
- 风险：如果你希望财务/老板专属信息对其他人不可见，这个方案不够。

## 方案 B：视角 + 权限分离（更标准，可扩展）
**核心思想**：
- 用户（User）有多个角色：`roles: RoleID[]`
- 用户当前处于一个视角：`activeRole: RoleID`
- 权限是能力集合（capabilities），可由 roles 决定；视角只是默认展示。

落地效果：
- 角色切换菜单只显示“当前用户拥有的角色”，不是系统全角色；
- Sidebar/路由按权限控制（没权限的模块不出现，也进不去）；
- 页面默认展示按 activeRole（例如默认 Tab、默认筛选、默认工作流）。

## 4) （可选）加上真正的权限边界
- Sidebar 根据权限隐藏菜单项
- Router 增加路由守卫（没权限跳回 Dashboard 并提示）
- 重点先做：财务模块仅 FINANCE/ADMIN 可见

## 5) 验证方式
- TypeScript 编译通过（`npm run build`）
- 手工验证 4 个场景：
  - 单人多角色：老板+销售（ADMIN+CONSULTANT）切换视角，默认面板变化
