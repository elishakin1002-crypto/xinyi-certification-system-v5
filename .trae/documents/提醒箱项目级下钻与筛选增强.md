## 结论（为什么你说得对）
当前“聚合视图”只给了 3 条 samples，“明细视图”又是全量混排——当项目多时，确实会出现你说的“想看某一个项目明细，要在二三十条里翻”的低效问题。

## 改造目标
- 在聚合卡片上就能“一键看全该项目/客户的所有明细”，不需要跳到全量混排里找。
- 在明细视图中支持“按对象过滤/跳转”，让明细不再是无序大列表。

## 方案（落地到 UI 行为）
### 1) 聚合卡片增加“查看全部明细”下钻
- 每张聚合卡片新增按钮：查看全部（N）
- 点击后：
  - 自动切换到“明细视图”
  - 自动启用过滤条件（linkType+linkId），只显示该项目/客户的原子提醒

### 2) 明细视图顶部增加“对象筛选器”
- 在明细列表上方新增：
  - 下拉选择（来自 aggregatedReminders）：选择某个项目/客户（显示名称 + 计数）
  - 当前筛选 Chip（例如：客户【XX】·项目【YY】）+ 清除按钮
  - 关键字搜索（按 title/content 过滤）

### 3) 明细列表可选“按对象分组”
- 为了避免仍然混排：
  - 明细视图支持按对象分组显示（默认开启或沿用“筛选后单对象”场景无需分组）
  - 未筛选时，也能快速折叠/展开某个对象的明细块

## 实现改动点
- 仅改工作台页面 [Dashboard.tsx]：
  - 新增 state：detailScope（linkType/linkId）、detailSearch、detailGrouped
  - 聚合卡片新增“查看全部”按钮，把 detailScope 写入并切到 detail view
  - 明细渲染改为：先按 detailScope + detailSearch 过滤，再按是否分组渲染
- 不改扫描规则与 reminder 生成（业务规则保持不动）。

## 验证方式
- 打开工作台提醒箱：
  - 聚合视图点击任一对象的“查看全部（N）”→ 明细视图只剩该对象提醒
  - 明细视图用下拉切换不同项目/客户 → 列表即时变化
  - 清除筛选 → 恢复全量明细
- 本地构建：npm run build 通过。
