# T-客户载体-PDCA-最小闭环-v1 实施方案

## 目标
建立**客户（Customer）作为长期唯一载体**，确保项目结束后的结果回写到客户，实现最小 PDCA 闭环。

## 1. 数据模型调整 (`types.ts`)

### Customer (客户)
新增以下字段以支持长期关系维护：
- `cooperationCount`: number (合作次数)
- `lastProjectAt`: string (最近一次项目时间)
- `lastProjectType`: string (最近一次项目类型)
- `nextOpportunity`: string (下一次机会)
- `customerNotes`: string (客户认知沉淀)

### Project (项目)
- `customerId`: string (显式关联客户ID)

## 2. 核心逻辑实现 (`context/AppContext.tsx`)

### 升级 `completeProject` 函数
在项目完成时（Status = Completed），强制执行以下“三步走”逻辑：

#### Step 1: 智能绑定客户 (Bind)
- **识别来源**：
    - 若项目来自线索 (`LEAD:xxx`)：根据线索的 `unifiedSocialCreditCode` 或 `company` 查找现有客户。
    - 若项目来自合同：根据合同的 `customerName` 查找。
    - 若无关联：尝试根据项目名称中的客户名查找。
- **自动创建**：
    - 若未找到匹配客户，基于现有信息（线索详情或项目/合同名称）**自动创建新客户**。
- **双向绑定**：
    - 将 `customerId` 写入 Project。
    - 确保 Project 最终指向唯一的 Customer。

#### Step 2: 结果回写 (Write-back)
更新 Customer 的统计字段：
- `cooperationCount` += 1
- `lastProjectAt` = 当前完成时间
- `lastProjectType` = 项目类型

#### Step 3: PDCA 闭环 (Next Step)
根据项目属性推断 `nextOpportunity`：
- **规则**：若项目内容包含“体系”、“认证”等关键词 → 默认为“年审”。
- **兜底**：其他情况 → 默认为“待评估”。
- 将此推断结果写入 Customer，形成销售线索闭环。

## 3. 界面展示
- 确保客户数据结构更新后，现有客户列表和详情页能正常读取新字段（无需开发新页面，但需确保数据层兼容）。

## 验证标准
1.  线索转项目，项目完成后，客户列表中应自动出现该客户（若之前没有）。
2.  客户详情中，`cooperationCount` 应正确增加。
3.  客户详情中，应能看到 `nextOpportunity`（如下一次是“年审”）。
