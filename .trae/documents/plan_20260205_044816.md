# T-001 硬结果实施方案

根据您的【立即执行｜硬结果版】指令，我将对系统进行全方位的规则重塑与闭环修复。

## 1. 数据模型重构 (`types.ts`)

### Project (项目)
- 新增 `costStatus`: `'待补全' | '已确认'`
- 新增 `projectAmount`: `number` (必须大于0)

### Customer (客户)
- 新增 `totalAmount`: `number` (历史累计)
- 新增 `yearAmount`: `number` (当年累计)
- 新增 `level`: `'A' | 'B' | 'C'` (系统自动计算)

## 2. 业务逻辑升级 (`context/AppContext.tsx`)

### 线索转项目硬锁 (`createFollowUpProjectFromLead`)
- **前置检查**：
  - 若 `lead.status === 'Converted'` -> 抛错拒绝。
  - 若存在 `contractRef === LEAD:{id}` 的项目 -> 抛错拒绝。
- **初始化**：
  - 新项目 `costStatus = '待补全'`。
  - 新项目 `projectAmount = 0` (或留空)。
- **后置动作**：
  - 成功创建后，立即将 `lead.status` 更新为 `Converted`。

### 项目完成强校验 (`completeProject`)
- **阻断条件**：
  - 若 `costStatus !== '已确认'` -> 拒绝完成，提示补全费用。
  - 若 `projectAmount <= 0` -> 拒绝完成。
- **价值回写**：
  - 成功完成后，调用内部函数 `recalcCustomerStats(customerId)`。
  - 累加该客户所有 `Completed` 且 `costStatus='已确认'` 的项目金额，更新 `totalAmount` / `yearAmount` / `level`。

## 3. 界面与权限 (`pages/Customers.tsx`, `pages/Projects.tsx`)

### 权限隔离
- 在 `Customers.tsx` 中，根据 `currentUser.role` 判断：
  - 若非 `admin` 且非客户负责人 -> 隐藏金额与评级字段（显示 `***` 或锁图标）。

### 详情页修复
- “最近项目”仅展示满足 `Completed + 已确认` 的真实项目。
- 过滤掉 `Self-Operated` 等无效占位符。
