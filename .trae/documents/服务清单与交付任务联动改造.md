# T-007 项目重构计划：服务驱动架构

## 1. 数据模型升级 (`types.ts`)

我们将强制执行四层模型：**项目 -> 服务 -> 任务 -> 模板**。

* **新增类型**：

  * `ServiceCategory`（服务分类）：'体系认证' | '产品认证' | '政府项目' | '生产许可' | '其他'。

  * `ServiceItem`（服务项）：增加 `category`（分类）和 `progress`（计算进度）。

* **修改**：

  * `Project`（项目）：确保 `progress`（进度）由服务进度推导得出。

  * `TaskTemplate`（任务模板）：增加 `category` 用于自动匹配。

## 2. 模板智能中心 (`constants.ts`)

我们将构建系统的“大脑”来理解服务名称。

* **服务字典 (`SERVICE_CATALOG`)**：

  * 将关键词（如 "ISO9001", "三体系"）映射到 `ServiceCategory` 和默认 `TemplateID`。

* **扩展模板库**：

  * 添加针对 "ISO9001", "高企申报", "产品认证" 等的具体模板。

## 3. 核心逻辑重构 (`AppContext.tsx`)

`addProjectServiceItem` 函数将成为智能核心。

* **智能添加服务**：

  1. **输入**：服务名称（如 "ISO9001 认证"）。
  2. **分类**：自动检测分类（如 '体系认证'）。
  3. **匹配模板**：查找最佳模板（管理员自定义 > 系统内置 > AI 兜底）。
  4. **生成**：创建 `ServiceItem` 并生成关联的 `ProjectTask`（通过 `serviceItemId` 关联）。

* **进度计算**：

  * **服务进度**：核心任务的平均完成率。

  * **项目进度**：所有服务的加权平均。

## 4. UI 界面改造 (`pages/Projects.tsx`)

重构项目详情弹窗以反映层级结构。

* **服务卡片布局**：

  * 以卡片/区块形式展示服务。

  * 在所属服务*内部*展示任务。

* **操作控件**：

  * “添加服务”（主操作）。

  * “添加任务”（次级操作，绑定到具体服务）。

  * **移除手动进度**：禁用手动进度条，仅显示计算值。

## 执行步骤

1. **类型与常量**：定义 Schema 和字典。
2. **Context 逻辑**：实现智能添加服务和进度计算逻辑。
3. **UI 重构**：更新 `Projects.tsx` 以可视化“服务-任务”层级。
4. **兼容性**：确保现有未关联服务的任务仍然可见（归入“其他”或“未分类”）。
