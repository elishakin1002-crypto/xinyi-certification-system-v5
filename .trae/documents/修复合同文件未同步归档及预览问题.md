# 合同文件同步归档修复与经验沉淀

## 1. 经验沉淀（已执行）
您提的建议非常棒。我已经将这条经验写入了系统的核心记忆（Core Memory）中：
> **经验：AI识别与文件归档同步机制**
> 在处理文件上传与AI识别功能时，必须确保上传组件（如 IngestionUploader）在回调中传递原始 File 对象，以便调用方能同时获取 AI 结果和文件本身进行归档，避免“识别了但没存文件”的问题。

这意味着未来我在处理类似任务（如线索、客户、知识库的附件上传）时，会自动检索并应用这条规则，防止重蹈覆辙。

## 2. 本次修复方案（执行层）
基于上述经验和之前的无副作用评估，我将执行以下操作：

1.  **扩展组件回调** (`components/IngestionUploader.tsx`)：
    - 修改 `onSuccess` 的调用处，将原始 `file` 对象作为第二个参数传出。
    - `onSuccess(result, job.files[0])`

2.  **实现文件归档** (`pages/Contracts.tsx`)：
    - 在 `IngestionUploader` 的 `onSuccess` 回调中接收这个 `file` 对象。
    - 如果存在 `file`，立即为其创建 `blobUrl` 并添加到 `fileAttachments` 状态中。
    - 这样，当用户点击“确认录入”时，这个文件就会被包含在 `attachments` 列表中一并保存。

3.  **验证预览**：
    - 由于保存了真实的 `blobUrl`，预览功能将自动恢复正常，无需额外修改代码。

这个方案既解决了当前问题，又通过记忆机制实现了“吃一堑长一智”。
