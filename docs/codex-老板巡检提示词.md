# 会话 W：模拟老板巡检

> 这份和「会话 Y（角色链路实跑）」互补，**建议先跑这份**，它最快见效。
> Y 是顺着流程走一遍；这份是**按老板的眼睛扫一遍**。

---

你在 `信义认证系统 V5.0` 仓库里工作。浙江信义企业管理有限公司
（温州，13 人，ISO 体系认证咨询），下周上线。

**这一轮你要扮演的是老板金恩来，用他的方式检查这个系统。**

## 他是怎么检查的（照着做，别自创方法）

他不读代码。他的动作模式高度固定，过去两周每一次他找出问题都是这么找的：

1. **打开一个页面，先盯住顶部那四张卡。**
   逐张问自己：这个名字，和这个数字，是一回事吗？
2. **然后看下面的列表。**
   问：卡上写 3，下面是不是 3 行？不是的话，为什么？
3. **点一下卡片。**
   问：列表变了吗？变成的是不是这张卡说的那些？
4. **换一个角色重新登录，打开同一页。**
   问：数字变了吗？**应该**变吗？
5. **做一个动作，然后去别的页面找它。**
   问：我刚建的东西，在下游那个页面里找得到吗？
6. **刷新一次，再等一会儿。**
   问：我刚才做的，还在吗？

他找到的每一个问题都长这样：

- 「逾期任务是 0，下面卡片已逾期是 5？字段不统一，显示也不关联？」
- 「合同管理与我有关的包括『嘉力』，而项目管理中与我有关的不包括『嘉力』，怎么回事？」
- 「我用合同识别创建合同并同步创建客户，合同管理的详情中显示已经立项，
   结果在项目管理里没有该项目」
- 「情报雷达点『标记已分拣』，点了没反应」
- 「风险与提醒、风险与异常，是不是重复内容？」

注意这五条的共同点：**全部是"两个地方对不上"或"点了没效果"**，
而且**全部不报错**。控制台没红字、测试全绿、页面打得开。

**所以你这一轮不许读代码找问题。** 代码只能用来解释你已经在界面上
看到的现象。结论必须来自界面。

上一轮的教训就在这：你交了一份按代码形状组织的报告，
找到了真问题，但老板自己用十分钟又撞出三个你没发现的 ——
因为那三个只有做完动作再去下游看一眼才会暴露。

## 账号

自己建一次性账号，六个角色各一个，前缀 `uat-`，密码随机生成。
参考 `scripts/check-intel-fetch.mjs` 的做法（`server/authStore.js` 的 `createUser`）。

**不要向任何人索取密码，不要读 `.env` / `.env.local` 里的任何值，
不要把密码写进报告。**

# 第一遍：把所有卡片摊开对一遍

这是这一轮的主要产出。

## 要扫的页面

**六个角色 × 每个他能进的页面。** 别只看总助 —— 过去有一次走查只查了
总助的账号，漏掉的正是别的角色才看得见的问题。

页面清单（以实际菜单为准，少了自己补）：
工作台、我的任务、线索管理、客户管理、合同管理、项目管理、
不符合项管理、知识中心、财务、情报雷达、战略管理、员工账号、审计日志。

## 每张卡填这张表

```
页面：项目管理        角色：咨询顾问        范围筛选：与我相关
┌──────────────────────────────────────────────────────────────┐
│ 卡片名          │ 数字 │ 它数的到底是什么 │ 点了之后列表几行 │ 对得上？│
├──────────────────────────────────────────────────────────────┤
│ 进行中项目      │  3   │ 项目            │        3        │   ✅   │
│ 7 天内要交      │  1   │ 项目            │        1        │   ✅   │
│ 有逾期任务的项目│  2   │ ？              │        5        │   ❌   │
└──────────────────────────────────────────────────────────────┘
```

「它数的到底是什么」这一列，**必须从界面判断**：
点进去数一数下面有几行，行里是项目还是任务。
判断不了就写「说不清」—— **说不清本身就是问题**，
因为同事也会说不清。

## 四个必问

每张卡都要过这四问，**答不上来的写进报告**：

1. **名字和数字是一回事吗？**
   典型病：名字叫「…的项目」，数的却是任务条数。
2. **点进去，列表条数等于卡上的数字吗？**
   不等于的话，是设计如此还是 bug？设计如此的话，界面上说了吗？
3. **这张卡跟着筛选器变吗？**
   把状态、类别、范围、搜索各改一次，看卡片动不动。
   动或不动都可以，但**必须说得清是哪种**，而且界面上要让人看得出来。
   人最容易被骗的就是：他筛了「进行中」，卡片却还在按全部算。
4. **两张卡会不会其实是同一件事？**
   点 A 卡和点 B 卡，如果列表一模一样，那就是重复内容 —— 该合并。
   （这个已经踩过一次：「有任务卡住的项目」和「有逾期任务的项目」
   在项目只有两种状态时条件完全等价。）

## 还要做的三件横向对比

### A. 同一个词，跨页面对一遍

把所有页面上出现的同一个词抓出来，比较它们的数字：

| 词 | 在哪几页出现 | 各是多少 | 应该相等吗 | 实际 |
|---|---|---|---|---|
| 逾期任务 | 工作台 / 我的任务 / 项目管理 | | | |
| 逾期回款 | 工作台 / 财务 / 合同管理 | | | |
| 进行中项目 | 工作台 / 项目管理 | | | |
| 客户总数 | 工作台 / 客户管理 | | | |
| 与我相关 | 项目 / 合同 / 客户 / 线索 | | | |

**不相等而又叫同一个名字的，全部写进第一档。**
这正是老板最反感的那类：「字段不统一，显示也不关联？完全看不懂！」

口径基准在 `src/modules/glossary.ts`（术语表），
里面每条都写了「数的是什么、包不包括什么」。界面对不上就是界面错。

已定的几条口径，照着核：
- 今天到期的任务和回款，**都不算逾期**
- 没填日期的，**不算逾期**（没约定就没有迟到）
- 已跳过的任务算了结，**不算未完成**
- 已结项项目里的残留任务，**不进「我今天的活」**
- 客户总数 = **建了档就算**
- 没填日期的提醒进「待安排」，**不进「今天要做」**

### B. 同一条数据，跨角色对一遍

挑三条真实数据（一个客户、一个合同、一个项目），
用六个角色分别登录，记录每个角色看到什么：

```
项目「浙江嘉力…」
  总经理   看得到？__  金额显示__  能改？__
  总助     看得到？__  金额显示__  能改？__
  顾问     看得到？__  金额显示__  能改？__   ← 顾问按设计看不到金额，应显示 ¥***
  销售     看得到？__
  财务     看得到？__
  系统管理员 看得到？__
```

**「某个角色看不到」不一定是 bug，但必须说得出是为什么。**
说不出理由的，写进报告 —— 「合同管理里有、项目管理里没有」
就是这样被发现的。

### C. 重复内容找一遍

老板问过：「风险与提醒、风险与异常，是不是重复内容？」

把所有页面的板块标题列出来，找语义接近的两组，各点进去看内容：
- 内容一样 → 重复，该合并
- 内容不一样 → 名字起坏了，该改名

# 第二遍：做几个动作，然后去下游找

选五个最常用的动作，每个做完执行「三看」。

**三看**（每个动作之后都要做，一个都不能省）：

1. **看下游**：这个动作产生的东西，**在哪几个页面应该出现**？逐个打开核对。
   至少包括：对应的管理页、工作台的卡片数字、我的任务、
   提醒铃铛、相关客户/合同的详情页。
2. **看刷新**：按 F5，**再等 60 秒**（有些是定时轮询），还在吗？
3. **看换人**：换个角色登录，他看得到吗？数字和刚才一样吗？

五个动作：

| # | 动作 | 下游至少要看这几处 |
|---|---|---|
| 1 | 线索转客户 | 客户管理有没有 / 线索状态变了没 / 工作台客户数动了没 |
| 2 | 建合同（用「新建客户」而不是选已有客户） | 客户建出来没 / 公司名带过来没 / 合同列表 / 财务应收 |
| 3 | 从合同立项 | 项目管理**真的有**吗 / 负责人是谁 / 换个角色还看得到吗 / 任务生成没 / 我的任务里有没有 |
| 4 | 把一条任务点「进行中」，再点另一条「跳过」并填原因 | 刷新后还是这两个状态吗 / 已跳过的有没有被算进逾期 |
| 5 | 标记一笔回款已收 | 合同回款进度 / 财务 / 工作台营收 / 逾期回款金额 |

第 3 个 2026-09-15 出过事（项目建出来了但不属于任何人，
于是所有人的「与我相关」都看不到它）。第 4 个也出过事
（服务端只认两种状态，「进行中」和「已跳过」会被静默改回「待处理」）。
两个都修了 —— **你要验它们是真的修好了**。

## 报告写法

写到 `docs/老板巡检报告.md`：

```markdown
# 老板巡检报告（YYYY-MM-DD）

## 零、一句话结论
扫了 __ 个页面 × __ 个角色，共 __ 张卡。
其中 __ 张「名字和数字对不上」，__ 处「同一个词在两页数字不同」，
__ 处「点了没效果」。最该先修的是：……

## 一、卡片对照表
（每个页面一张表，六个角色都要有；相同的可以合并写"六个角色一致"）

## 二、对不上的地方
### 1. <一句话，用老板会说的话写>
- **在哪看到**：角色 / 页面 / 哪张卡
- **两边分别是什么**：A 显示 X，B 显示 Y
- **复现步骤**：1. … 2. … 3. …（别人照着能重现）
- **是哪一问发现的**：四个必问的第几问 / 三看的第几看
- **影响谁**：哪个角色、哪一步会看不懂或干不下去
- **严重程度**：□挡住上线 □能绕过但很别扭 □小瑕疵

## 三、同一个词跨页面对照
（那张表，填满）

## 四、同一条数据跨角色对照
（那三条数据的六角色表）

## 五、疑似重复内容
每组写：两个名字 / 各自内容 / 结论（该合并 or 该改名）

## 六、五个动作的三看结果
每个动作一张小表，写清每一看的结果。

## 七、扫过但没问题的
按页面列，每页一句话。**没写进这一节的就当作没扫过。**

## 八、我建的账号和造的数据
- 账号：uat-xxx ×6（已删 / 已停用）
- 数据：UAT- 开头的 N 条，分别是……
```

## 硬性约束

1. **不许改业务代码。** 只巡检、只出报告。
2. **不许用读代码代替看界面。** 结论必须来自界面上真实发生的事，
   代码只用来解释你已经看到的现象。
3. **每条发现必须有复现步骤。**「感觉不对」不算，
   「点 A 再点 B，本该是 C，实际是 D」才算。
4. **造的数据一律 `UAT-` 前缀**，报告里列清。
   **不许删任何不是你造的数据** —— 库里现在只剩线索和账号，
   是老板故意清空的，他要在干净的库上看联动。
5. **不许跑破坏性命令。** 不重置、不 `git checkout .`，
   不用 `pkill -f "server/app.js"` 这种模式杀进程（文件名会撞车，
   误杀过别人的开发服务器）。要停进程用 PID。
6. **3000/3001 可能被别的项目占用**，起服务前先
   `lsof -nP -iTCP:3000 -sTCP:LISTEN` 看清是谁的。
7. **烧 token 的动作各跑一次就够**（合同识别、情报抓取、战略分析、AI 助手）。
8. **密码和密钥不进报告、不进仓库、不进对话。**

开始前读 `CLAUDE.md`，特别是第六章「怎么防止头重脚轻」第 2 条的三个问题
（一致性 / 联动 / 闭环）—— 你这一轮扫的就是这三样。
