## 一、先回答「为什么出现这样的情况」

### 根因

手机端头部挂着 `overflow-hidden`（本意是防长标题撑破布局），
而账号菜单是 `absolute top-full` —— 定位在头部**下边缘之外**。

头部高 56px、`overflow:hidden` → **面板 100% 被裁掉，一个像素都画不出来。**

受害的**不止账号菜单**：

| 面板 | 状态 |
|---|---|
| 账号菜单（头像） | 我 9/10 加上去的，加上去就是坏的 |
| **铃铛面板** | **更早就坏了**，一直没人报 —— 手机上点铃铛没反应，大家以为是自己没点到 |

你截图里右下角那个问号是帮助悬浮按钮，一直都在，不是点击的结果。

## 二、我的测试为什么没发现 —— 这是重点

我确实测了，而且测「**过**」了。问题在**判据错了**：

```js
const r = el.getBoundingClientRect();
r.width > 0 && r.height > 0 && r.right <= innerWidth   // → true，我判定通过 ✅
```

**`getBoundingClientRect` 报的是布局几何，跟祖先有没有把它裁掉无关。**
被 `overflow` 裁掉的元素，rect 照样返回原来那个位置、原来那个尺寸。

实测证据（修复前，生产）：

```
rect说在视口内 : true        ← 我当时看的
菜单真的可见   : false       ← 真相
裁掉它的祖先   : HEADER ... [overflow:hidden]
```

### 更要紧的是：这是同一类错误的第二次

坑 #10 是「`position:fixed` 元素的 `offsetParent` 恒为 `null`」——
当时三层帮助的「先讲当前弹窗」整套逻辑一次都没生效过，也不报错。

两次的共同点：

> **用了一个不表示自己以为的含义的 DOM 测量，然后拿它当"验证通过"。**

同一个项目栽第二次，**说明这不是手滑，是方法问题。** 所以整改的重点不是修这一个 bug。

## 三、整改

### 1. 修根因

去掉手机端头部的 `overflow-hidden`，长标题改用 `truncate`
（该省略号的省略号，而不是把整行连同垂出来的东西一起裁掉）。
**一次修好两个面板。**

### 2. 换掉验证方法 —— 只有一个正确判据

```js
el.contains(document.elementFromPoint(x, y))
```

问的是「那个坐标上**实际画着的**是不是它」。于是 overflow 裁剪、
z-index 遮挡、opacity:0、被浮层盖住 —— 全都会如实反映，不用一条条去想。

落地：`scripts/ui-visibility-check.mjs`，不可见时还会**把裁掉它的祖先找出来**
（只说"不可见"等于让修的人再查一遍）。

### 3. 静态兜底

`tests/header-dropdown-clipping.test.js` 四条：

- 手机端头部不许再有 `overflow-hidden`
- 长标题必须有 `truncate` + `min-w-0`
- 可见性检查必须用 `elementFromPoint`，不许退回尺寸判据
- HelpHub 不许退回 `offsetParent`

### 4. 写进坑文档

`docs/踩过的坑.md` 新增 **10b**，紧挨着 #10 放 —— 让下一个人一眼看到这是同一类。

并补了一条通则：

> 给一个容器加 `overflow-hidden` 之前，先问「有没有东西是从我这里垂出去的」
> —— 下拉、气泡、提示框全算。

### 扫描过程中我的脚本自己出过一次错，值得记

第一遍结果是 **OK / ✗ 交替出现**，6 个页面报"被 `DIV.fixed inset-0 z-40` 盖住"。

差点当成 6 个产品故障报给你。查下来是**我的测试脚本的 bug**：
我用「点击 `div.fixed.inset-0.z-40`」来关菜单，
而那个元素是**侧边栏容器** —— 点它反而把侧边栏打开了，于是下一页被盖住。

改成「再点一次头像切换关闭」后，13/13 全绿。

**教训和上面是同一条**：测试脚本本身也会骗人，交替出现的规律性失败
通常是测试的问题，不是产品的问题。

## 五、你提的第三方合作：已改成项目属性

你说「第三方服务各类服务都有」。那它**不可能是服务类型的属性** ——
体系认证可能外包、食包可能外包，同一大类里这一单外包下一单自己做。

改法（和 `billable` 一个道理：**属性，不是类别**）：

```ts
/** 这一单是不是和第三方合作做的 */
outsourced?: boolean;
/** 合作方名称 —— 否则「谁做的」这条链就断在这里 */
vendorPartner?: string;
```

派活逻辑相应分成两条路，**说法不一样因为该做的事不一样**：

| 情况 | 系统说 |
|---|---|
| 这一单勾了外包 | 「这一单走第三方，不派内部负责人 —— 把合作方和对接人填上，否则将来查『这活谁做的』会断在这里」 |
| 这个大类内部没人做（医疗器械/饲料） | 「内部没人做，这类一律走第三方 —— 记得写清合作方和对接人」 |

原来那个 `OUTSOURCED_GROUPS` 改名成 `NO_INHOUSE_OWNER_GROUPS` ——
名字要说清它只是「内部没人做」那一小部分，不是「走第三方的全部」。

**还没做**：建项目表单上那个勾选框，以及外包成本的结算口径。等你确认要不要现在做。
