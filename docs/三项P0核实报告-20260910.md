## P0-3　员工页勾选额外权限 —— 早就做完了

### 实际状态

`pages/Employees.tsx` 里的「单项权限微调」是一套完整可用的界面：

- 折叠面板，标题上带「额外 N · 收走 N」计数
- 逐个动作两个按钮：**额外给** / **收走**
- 高风险动作标红提示
- 角色自带的动作用灰字标出「角色自带」，避免重复勾选
- 同一个动作不能既给又收 —— 勾一边自动取消另一边

服务端 `extra_actions` / `denied_actions` 两列、以及鉴权链路，早就打通了
（`server/authStore.js`，含 `ALTER TABLE ... ADD COLUMN IF NOT EXISTS`）。

### 那为什么感觉「没做」

生产库实测：**0 个账号配置过额外权限**。

```sql
select name, extra_actions, denied_actions from auth_users
where extra_actions::text <> '[]' or denied_actions::text <> '[]';
-- (0 rows)
```

不是不能用，是**还没到用的时候**。这个功能的典型场景是「总助代管」——
比如让李智薇临时拿到某个通常只有财务才有的动作。等测试期真的出现这种需求，
它就在那儿，不用再开发。

### 你判断的「对总助尤其重要」是对的

而且已经具备。测试期可以直接让李智薇试：
给她加一个 `CONTRACT_UPDATE` 之类的动作，看她那边是不是立刻能操作。

## P0-4　账号有效期 + 到期前 7 天提醒 —— 做了一半，今天补齐

### 此前的真实状态

| 部分 | 状态 |
|---|---|
| 有效期输入框 | ✅ 有（`pages/Employees.tsx`，留空 = 永久有效，配了说明文字） |
| 服务端到期拦截 | ✅ 有（`isAccountExpired`，到期直接登不进来） |
| 到期后的提示语 | ✅ 有（昨天刚补：「这个账号已到期。找系统管理员延长有效期后再登录。」） |
| **到期前 7 天提醒** | ❌ **全库搜不到，根本不存在** |

所以它的实际形态是：

> 兼职或临时合作方某天早上突然登不进系统，打电话过来问，
> 这时候才有人想起来「哦有效期到了」—— 而那正是最忙的时候。

**事后说得再清楚，也不如事前提醒一句。**

### 今天补的

在 `runSystemScans` 里加了第 5 段扫描：

- 到期前 **7 天内**（含当天）触发
- 发给 **ADMIN / SYS_ADMIN** —— 只有他们改得动有效期。
  发给本人没用：他既改不了也帮不上忙，徒增焦虑
- 停用的账号不再提醒
- 铃铛点进去直接跳「员工账号」页（`linkTypeRoute` 里加了 `employee: '/employees'`）

文案：

> 🔑 账号 3 天后到期
> 【商春姿】的账号有效期到 2026-09-13。到期后他会直接登不进来 ——
> 还要继续用就去「员工账号」里改有效期；确实不用了就不用管，到期自动失效。

### 过程中挖出一个更深的根因

写完提醒，实测**一条都发不出来，而且不报任何错**。

查下来是 `hydrateProfilesFromAuth` 里的字段映射：

```js
setUserProfiles(accounts.map((a) => ({
  id, name, roles, activeRole, positionTags, reportsToUserId   // ← 只挑了 6 个
})))
```

**这是白名单式映射，`accountExpiresAt` 在这一步被静默丢掉了。**
服务端返回了、类型定义里也有，但它进不了前端 ——
于是我的判断条件恒为假，提醒一条也不发，还不报错。

这类映射是静默丢数据的高发地：加字段的人改了后端和类型定义，
唯独想不到还有这么一层白名单。**它是这份数据进入前端的唯一入口。**

已补上 `accountExpiresAt` 和 `status`（顺带 `UserProfile` 类型加了 `status`）。

### 验证

设了一个 3 天后到期的测试账号，实测提醒正确生成、文案正确、
`forRole` 正确、`linkType=employee` 正确。验完已清理测试数据。

4 条测试钉住：`tests/account-expiry-reminder.test.js`
—— 其中第一条专门盯那个字段映射，因为它才是根因。

### 你判断的「测试账号/兼职账号以后会需要」是对的

而且**测试期就用得上**：这次四位同事的账号如果设了有效期，
到期前你会先收到提醒，而不是等他们打电话来。

## P0-6　合同附件转对象存储 —— 确实没做

### 实际状态

附件现在落在服务器本地磁盘：

```js
// server/routes/uploads.js
const UPLOAD_ROOT = path.resolve(process.cwd(), process.env.XINYI_UPLOAD_DIR || '.runtime/uploads');
```

### 当下不紧迫的三个理由

1. **生产上该目录还没建起来** —— 一个附件都没传过（系统还没真正投用）
2. **磁盘还很空**：50G 用了 7.2G，剩 40G（16%）
3. **图片压缩已经做了**（P0-15，实测 3.21MB → 358KB，省 89%），
   所以是线性增长，不是爆炸式

按 60–100GB/年 的量估，全员铺开后**不到一年**会满。

### 卡在哪

不是技术问题，是**要先定用哪个 COS 桶、给一组密钥**。
这个只有你能提供。密钥给我时放 `.env.local`，别贴进对话。

### 你判断的「正式使用前要解决」

我的看法略有不同：**可以在测试期之后、全员铺开之前做**，不必卡在现在。
理由是现在 0 附件、40G 空闲，而测试期本身会产生第一批真实附件 ——
那时候才知道实际的文件大小分布，迁移方案能定得更准。

如果你希望现在就做，给我桶和密钥即可，工作量大约半天（上传路径已经收敛在一处，
