## 为什么要有这一步

正规流程里，「开发测完」和「用户来测」之间有一层叫 **产品负责人走查（dogfooding）**：

> **系统的主人自己先完整用一遍。**

没有哪家公司会把产品负责人自己都没走过的东西交给用户 ——
因为用户遇到的第一个坎就会让他们失去信心，而那个坎往往一眼就能看出来。

## 先解决你担心的「假数据污染」

**在本地随便造，不会污染任何东西。** 本地库和生产库是两个库，互不相干。

而且我已经给你做好了一键还原：

```bash
npm run walkthrough:status    # 看现在比基线多造了多少数据
npm run walkthrough:reset     # 一键回到走查前，假数据全清
```

基线已经拍好了（50.6 MB，客户 12 · 线索 455 · 合同 52 · 项目 28 · 工作日志 47），
**实测验证过：造一条数据 → reset → 确认消失。**

> 脚本对生产是**硬拦**的：连到生产地址会直接退出，不是提示，是拒绝执行。
> 这个项目被测试数据坑过 4 次（迁移 006/007/014/021），不能再来第五次。

**所以：放开手脚点，故意填错，故意乱填，越野蛮越好。** 走查的价值全在这里 ——
小心翼翼地点一遍，什么问题都查不出来。

## 第一段：销售主链路（演 总经理 `zengyunjun`）

**这条链是公司的命脉：从一条线索到收到钱。**

| # | 做什么 | 重点看什么 |
|---|---|---|
| 1 | 线索管理 → 新建一条线索，公司名随便填 | 建完**它在列表里吗**（踩过三次：被默认筛选藏起来了） |
| 2 | 给它加一条跟进记录 | 记录显示出来了吗；时间对吗 |
| 3 | 把它转成客户 | 转完线索状态变了吗；客户库里出现了吗 |
| 4 | 客户管理 → 打开刚转的客户，补一张证书 + **到期日填 20 天后** | 保存成功吗 |
| 5 | 点「排跟进提醒」 | **铃铛里出现 3 条吗**（到期前 30/15/7 天） |
| 6 | 回项目管理看 | **不该冒出「认证到期跟进」项目**（这个 bug 9/9 才修掉） |
| 7 | 合同管理 → 给这个客户建一份合同，金额填 **8000** | **列表里显示的是 8000 元还是 800000？**（库里存「分」）|
| 8 | 由合同建项目 | 服务内容填「ISO9001 体系认证」→ **有没有出现「建议：黄邦煜」+ 理由** |
| 9 | 财务 → 确认一笔回款 | 数字对吗；客户的累计金额跟着变了吗 |

**每一步都问自己：做完这一步，我知道下一步该去哪吗？**
如果不知道，那就是缺陷 —— 记下来。

## 怎么记问题

每条写四样，缺一不可：

```
① 哪个页面 + 演的哪个角色 + 什么屏幕宽度
② 我做了什么
③ 结果是什么
④ 我以为会怎样
```

分级：

| 级别 | 意思 |
|---|---|
| **阻断** | 干不了活：进不去、存不了、数据错 |
| **严重** | 有别的办法绕，但很难受；或数字不对 |
| **一般** | 界面别扭、文案看不懂 |
| **建议** | 希望有的新功能 —— **记录，测试期不做** |

最后一条是纪律：真实业务一跑，需求会像雪片一样来，全接就永远上不了线。
