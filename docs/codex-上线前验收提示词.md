# 会话 Y：六个角色的工作链路实跑

你在 `信义认证系统 V5.0` 仓库里工作。浙江信义企业管理有限公司（温州，
13 人，ISO 体系认证咨询），下周上线，13 个同事每天要用它干活。

**这一轮不是代码审查，是验收。**

## 先说清为什么这样要求

上一轮的横扫是按「代码里的问题形状」组织的，你于是去读代码。
读代码找到了一批真问题，但**老板自己用了十分钟，又发现了三个你没发现的**：

- 用合同识别建了合同+客户+项目，合同详情写「已立项」，
  去项目管理却找不到那个项目
- 在情报雷达点「标记已分拣」，刷新后又变回「待处理」
- 在战略管理点「让 AI 读这些数字」，转 60 秒后报「模型不存在」

这三个的共同点：**光看代码看不出来**。
第一个要「建完之后换个页面去找」，第二个要「点完之后刷新再看」，
第三个要「真点一次并等到它返回」。

所以这一轮的硬要求是：

> **每做完一个动作，必须去下游所有会显示它的地方看一眼，
> 并且刷新一次、换个角色再看一次。**

这句话是这整份提示词的核心。其它都是它的展开。

## 账号怎么来

**不要向任何人索取密码，也不要去读 `.env`、`.env.local` 里的任何值。**

自己建一次性账号，用完停用。参考 `scripts/check-intel-fetch.mjs` 的做法
（`server/authStore.js` 的 `createUser`）：

```
uat-admin-<时间戳>       roles: ['ADMIN']        总经理
uat-sysadmin-<时间戳>    roles: ['SYS_ADMIN']    系统管理员
uat-manager-<时间戳>     roles: ['MANAGER']      总助
uat-sales-<时间戳>       roles: ['SALES']        销售
uat-consultant-<时间戳>  roles: ['CONSULTANT']   咨询顾问
uat-finance-<时间戳>     roles: ['FINANCE']      财务
```

密码随机生成，**不要打印、不要写进报告、不要落盘**。

收尾规矩（重要）：
- 经手过合同/项目/审批的账号**删不掉是设计**（见 `server/authStore.js`
  的 `deleteUserIfUnused`）。删不掉就**停用**，绝不留一个能登录的活口。
- 报告里写清你建了哪几个账号、最后是删了还是停用了。

## 测试数据怎么造

**所有你创建的业务数据，名字前面加 `UAT-`。**
例如客户叫 `UAT-温州示例包装有限公司`，合同叫 `UAT-体系认证咨询合同`。

这样跑完之后能一次性识别和清理。报告最后要列出你造了哪些数据。

**不要删除任何不是你造的数据。** 库里现在只剩线索和账号，是老板
故意清空的，他要在干净的库上看联动。

## 六条链路

每条链路按「谁 → 做什么 → 下一个人在哪看到」写。
**每一步做完都要执行「三看」**（下面有定义）。

### 「三看」—— 每个动作之后必做

1. **看下游**：这个动作产生的东西，在**哪几个页面**应该出现？
   逐个打开核对。至少包括：对应的管理页、工作台的卡片数字、
   我的任务、提醒铃铛、相关客户/合同的详情页。
2. **看刷新**：按 F5 刷新，**再等 60 秒**（有些轮询是定时的），
   刚才那个变化还在吗？
3. **看换人**：用另一个角色登录，同一条数据他看得到吗？
   看到的数字和刚才那个角色一样吗？不一样的话，**应该**不一样吗？

第 3 条最容易漏，也最容易出事 —— 「合同管理里有、项目管理里没有」
就是这么发现的。

---

### 链路 1：从一条线索到收到钱（主干，最重要）

这条走通了，系统就能用；走不通，别的都白搭。

```
销售     线索管理：挑一条线索 → 转客户
销售     客户管理：确认客户建出来了，线索状态变成「已转化」
销售     合同管理：给这个客户建合同，填回款节点
总助     合同管理：从合同立项，指定负责人和交期
顾问     项目管理：看到这个项目了吗？服务项和任务自动生成了吗？
顾问     我的任务：这些任务出现在他的清单里了吗？
顾问     项目管理：做完一条任务 → 进度动了吗？工作台的数字动了吗？
顾问     项目管理：把一条任务点「进行中」，刷新，还是「进行中」吗？
顾问     项目管理：把一条任务点「跳过」并填原因，刷新，还是「已跳过」吗？
财务     财务：这笔应收出现了吗？金额对吗？（注意：库里存的是「分」）
财务     财务：标记一笔已收 → 合同的回款进度动了吗？工作台的数字动了吗？
总助     项目管理：走完结清单 → 结项
老板     工作台：营收数字动了吗？
```

**每一步之后做「三看」。** 特别注意这几个点：

- 建合同时**不选已有客户**，用「新建客户」，看公司名有没有自动带过来
- 立项时**不指定负责人**（如果界面允许），看建出来的项目谁能看见
- 顾问看得到合同金额吗？（设计上顾问看不到，应该显示 `¥***`）
- 一笔应收**不填到期日**，看它会不会被算成「逾期」
- 一笔应收**到期日填今天**，看它算不算「逾期」
  （口径：今天到期**不算**，见 `src/modules/glossary.ts`）

### 链路 2：合同识别（AI 一次建多样东西）

```
总助/销售   合同管理 → 录入合同 → 上传 PDF → AI 识别
            勾上「同步创建客户」和「同步立项」
            → 客户建出来了吗？合同呢？项目呢？
            → 合同详情写「已立项」，项目管理里**真的有**那个项目吗？
            → 那个项目的负责人是谁？换个角色登录，他看得到吗？
```

这条链路 2026-09-15 出过事：项目建出来了，但**不属于任何人**，
于是全公司每个人的「与我相关」都看不到它，包括刚建它的人。
已经修了，你要验它是真的修好了，**并且顺手找同类的**：
还有哪些自动创建的东西可能是无主的（提醒？任务？服务项？）。

会烧 token，**只跑一次**。

### 链路 3：证书到期 → 续证

```
销售/顾问   客户管理：给客户录一张快到期的证书
            → 提醒生成了吗？在谁的铃铛里？
            → 到期前 30/15/7 天三条都排上了吗？
总助        提醒 → 点进去 → 能直接开始跟进吗？出口在哪？
```

重点验**闭环**：提醒点进去之后，下一步点什么？会不会点进去是个死胡同。

### 链路 4：情报 → 线索

```
总助   情报雷达 → 抓取今日情报（会联网+调 AI，只跑一次）
       → 抓到了吗？抓不到的话，界面有没有说清是为什么？
       → 点一条「标记已分拣」→ 刷新 → 还是「已分拣」吗？
       → **等 10 分钟再看一次**（有个 10 分钟的轮询，
          2026-09-15 之前它会把人的分拣状态刷回「待处理」）
       → 点「转为情报研判任务」→ 生成了什么？在哪能看到？
```

注意：**情报的内容不进知识中心**，这是 2026-09-13 定的。
如果你在知识中心看到情报日报，那是 bug。

### 链路 5：不符合项 → 整改 → 关闭

```
顾问   不符合项管理：新建一条不符合项
       → 整改任务自动生成了吗？在谁名下？
       → 「我的任务」里出现了吗？
顾问   做完整改 → 关闭不符合项
       → 顶部「新增/关闭」两个数字分别怎么动的？
       → 「待整改」的那条会不会被算成「已关闭」？
```

### 链路 6：账号生命周期（系统管理员）

```
系统管理员   员工账号：新建一个员工 → 分配角色
             → 他能登录吗？看到的菜单对吗？
             → 每个菜单点进去，有没有「菜单看得见但请求 403」？
             → 改他的角色 → 他那边刷新后菜单跟着变了吗？
             → 停用他 → 他还能登录吗？他名下的记录还在吗？
             → 试着删除一个**经手过记录**的账号
                → 应该删不掉，而且提示要说清为什么、该用什么代替
```

最后一条是业务铁律：**「谁做的」这条链不能断。**
如果能删掉，那是严重 bug，写进第一档。

## 还要专门盯的几件事

这些是这个项目已经出过事的地方，每条链路里遇到都要留意：

| 盯什么 | 怎么验 |
|---|---|
| 金额 | 库里单位是**分**。界面显示 8000 元，库里应该是 800000 |
| 工时 | 0.5 小时不能存成 50（用 decimal 不用 amount） |
| 今天到期 | 任务和回款，**今天到期都不算逾期** |
| 没填日期 | 不算逾期（没约定就没有迟到），也不该冒充「今天到期」 |
| 已跳过 | 算了结，不算未完成，不该出现在待办和逾期里 |
| 已结项项目里的残留任务 | 不该进「我今天的活」 |
| 删了刷新又回来 | 删任何东西之后刷新、换角色，确认它真没了 |
| 空状态 | 每个列表在没有数据时，有没有说清「该怎么开始」 |

## 硬性约束

1. **不许改业务代码。** 这一轮只验收、只出报告。
2. **每条发现必须有复现步骤。** 「感觉不对」不算，
   「点 A 再点 B，本该出现 C，实际是 D」才算。
3. **不许用读代码代替实跑。** 代码可以用来解释你看到的现象，
   但**结论必须来自界面上真实发生的事**。
   上一轮就是因为只读代码，漏掉了三个老板十分钟就撞上的问题。
4. **不许跑破坏性命令。** 不删非你造的数据、不重置、不 `git checkout .`、
   不用 `pkill -f "server/app.js"` 这种模式杀进程（文件名会撞车，
   误杀过别人的开发服务器）。要停进程用 PID。
5. **密码和密钥不进报告、不进仓库、不进对话。**
6. **3000/3001 可能被别的项目占用**，起服务前先
   `lsof -nP -iTCP:3000 -sTCP:LISTEN` 看清是谁的。
7. **烧 token 的动作各跑一次就够**（合同识别、情报抓取、战略分析、
   AI 助手）。

开始前读 `CLAUDE.md`。

# 会话 Z：上线前常规核查

接着会话 Y 做。同样**只验不改**，写到 `docs/上线前常规核查报告.md`。

这一轮查的是正经系统上线前都要过一遍的那些东西。
按下面的清单逐项，每项写「验过 / 结论」，**没写的就当没查**。

### 1. 权限矩阵（六个角色 × 每个页面 × 每个动作）

这个项目的权限有**三份定义**，不是一份：
`ROLE_PERMISSIONS`（能看哪些菜单）、`ROLE_CAPABILITIES`（能做哪些动作），
都在 `constants.ts`；服务端还有一份从 `constants.ts` 解析出来的。
只改一处的典型症状是「**菜单看得见，但每个请求都 403**」。

做一张表：行是角色，列是页面，格子里写
「能进 / 进不去 / 能进但按钮 403」。
每个角色**逐个菜单点一遍**，每个页面**主要按钮点一下**。

仓库里有 `scripts/authz-matrix-live.mjs`，可以先跑它当底稿，
但**不能代替真点** —— 它检的是服务端答复，不是界面表现。

另外注意一个已知陷阱：
`checkActionPermission('X', {})` 和 `checkActionPermission('X')`
**结果相反**（`{}` 是 truthy，会触发「这条数据是不是我的」判断，
而空对象谁都不属于）。查所有新建类动作有没有误传 `{}`。

### 2. 数据边界

每种主要对象（客户/合同/项目/任务/应收）各试一遍：

- 空：一条都没有时，页面长什么样，有没有告诉人怎么开始
- 一条：只有一条时统计卡对不对
- 极值：金额 0、金额很大、日期是今天、日期是去年、日期留空
- 超长文本：公司名 100 字、备注 2000 字 —— 会不会撑破布局
- 特殊字符：名字里带 `<script>`、带引号、带 emoji、带换行
- 重复：同名客户建两次，有没有查重提示

### 3. 刷新与重新登录后的持久性

**每一个能改数据的动作**都要过这一关：

```
做动作 → 刷新 → 还在吗
       → 退出重新登录 → 还在吗
       → 换台浏览器（隐身窗口）登录 → 还在吗
```

第三步专门抓「只存在本地浏览器里」的假保存。
这个项目有两套存储（关系表 和 `app_state_latest` 的 JSON），
写漏一处的症状就是「我这台看得到、别人看不到」。
跑完可以用 `npm run checkup:consistency` 对账。

### 4. 重复提交与并发

- 每个提交按钮**连点三下**，会不会建出三条
- 两个窗口同时改同一条记录，后一个会不会把前一个悄悄覆盖
- 慢网下（浏览器开发者工具限速）点提交，有没有加载态、会不会重复提交

### 5. 错误提示能不能照着做

把能触发的错误都触发一遍（必填不填、格式错、权限不足、
删不掉的东西去删、网断了）。每条提示回答两个问题：

1. 它说清**后果**了吗？（不是只说「操作失败」）
2. 它说清**下一步该干什么**了吗？

项目规矩举例：
「不能删除」→「删了那些记录就变成『不知道谁做的』，这种情况用停用」。
达不到这个标准的提示语，列出来。

### 6. 手机端

主要页面在手机宽度（375px）下走一遍链路 1。
特别看：表格会不会横向溢出、按钮会不会被挤出屏幕、
弹窗能不能关掉、筛选器能不能点。

### 7. 中断与返回

- 弹窗填到一半关掉，再打开 —— 是空的还是留着上次的？哪种对？
- 浏览器**后退键**：各个页面按后退会怎样（这是 HashRouter，
  所有真实地址都是 `/`，路由在 `#` 后面）
- 详情页直接刷新（带 hash 的地址），还能打开吗

### 8. 附件与导入导出

- 上传 PDF / 图片 / 超大文件 / 不支持的格式，分别什么反应
- 上传完**换个角色**看，他下载得到吗
- Excel 批量导入：给一个格式对的、一个有错行的，
  错行有没有指出是第几行第几列错
- 导出的文件打得开吗、数字对吗（注意金额单位是分）

### 9. 时间边界

- 今天到期：任务、回款，都不算逾期
- 跨月/跨年：把系统时间相关的统计（本月营收、近 7 天）
  用月初、月末、年末的数据各试一次
- 时区：日期显示会不会差一天

### 10. 停用与删除的连带

- 停用一个员工 → 他名下的项目、任务、合同怎么显示？
  会不会变成「无主」而从所有人的「与我相关」里消失？
- 删一个客户 → 他的合同和项目怎么办？应该拦住还是级联？
- 删了之后刷新、换角色，确认它真没了（不是「删了刷新又回来」）

### 11. 定时任务和后台作业

`server/services/` 下有几个跟着服务一起起来的 job
（提醒生命周期、状态历史保留、模型自检）。
确认：服务起来时它们真的跑了吗？日志里看得到吗？
出错时是只警告还是会拖垮服务？

### 12. 首次使用体验

用一个全新账号第一次登录：
新手引导出现了吗？能跳过吗？跳过之后还能再打开吗？
每个页面有没有「本页详解」入口？
