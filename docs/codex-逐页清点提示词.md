# 第一部分：85 个格子，一个不许跳

对总表第一节的每一格，登录对应角色，打开对应页面，填这张表：

```
| 角色 | 页面 | 该进得去？ | 实际 | 首屏正常？ | 空状态说人话？ | 手机端 375px |
|------|------|-----------|------|-----------|--------------|-------------|
| 顾问 | 回款概览 | ❌不该 | 被拦✅ | — | — | — |
| 顾问 | 项目管理 | ✅该 | 进去了✅ | ✅ | ✅ | ⚠️表格横向溢出 |
```

## `—`（不该进）的格子怎么测 —— 这一步最容易被跳过

**不要只看菜单里有没有。** 菜单藏了不等于进不去。

在地址栏直接敲那个地址（注意是 HashRouter，形如
`http://localhost:3000/#/finance`），看：

1. 被挡住了吗？
2. 挡的时候说了什么？是「无权限」还是白屏／报错？
3. **挡住之后能回到哪里？** 有没有出口，还是卡在那一页。

能进去 = 权限漏洞，直接进报告第一档。
这个项目权限有**三份定义**（`ROLE_PERMISSIONS` 管菜单、
`ROLE_CAPABILITIES` 管动作、服务端还有一份解析出来的），
只改一处的典型症状就是「菜单看不见但地址能进」或者
「菜单看得见但每个请求都 403」。

## `✅`（该进）的格子看四样

1. **首屏有没有炸**：白屏、报错、控制台红字、数据一直转圈
2. **布局**：有没有东西被挤出屏幕、文字被截断、卡片错位、
   表格撑破容器、按钮叠在一起
3. **空状态**：这一页没有数据时说了什么？
   合格线是**告诉人怎么开始**，不是只写「暂无数据」
4. **手机端**：浏览器开发者工具切到 375px 宽，
   看表格会不会横向溢出、按钮会不会被挤出去、弹窗能不能关掉

# 第二部分：357 条可点文案，逐条点

对总表第二节列出的每一页的每一条文案，点一次，记录：

| 页面 | 按钮文案 | 点了有反应吗 | 反应对吗 | 有没有报错 | 备注 |
|---|---|---|---|---|---|

判「反应对吗」问三句：

1. **它做了它说要做的事吗？**
   （「导出」真的下载了文件吗？「重置筛选」真的全部重置了吗？）
2. **做完之后人知道下一步去哪吗？**
   成功提示只说「操作成功」不合格，要说清产生了什么、在哪能看到。
3. **点两下会怎样？** 连点三下会不会建出三条。

### 特别要抓的几种「点了没效果」

这个项目已经出过这几种，都不报错：

- **点了界面没变**，但后端其实成功了（徽章没跟着状态走）
- **点了界面变了，刷新又变回去**（轮询把人的决定盖了）
- **点了什么都没发生**，控制台一行 warn（请求 404 被吞掉）
- **按钮切到的筛选，列表根本不支持**（点了等于没点，还高亮着）

所以每个会改数据的按钮，点完都要**刷新一次再看**，
有轮询的页面（情报雷达）**再等 60 秒看一次**。

### 危险按钮单独列

删除、归档、停用、批量操作、重置、导入 —— 这些点之前先想清楚后果。

- 在 `UAT-` 数据上测，不要在别的数据上测
- 删不掉的东西（经手过记录的账号）要验**确实删不掉**，
  而且提示要说清为什么、该用什么代替
- 删掉之后刷新、换角色再看一次，确认是真没了
  （这个项目出过「删了刷新又回来」）

# 第三部分：六个角色的工作流各走一遍

前面两部分是静态清点，这一部分是动起来。
每个角色走完他自己那条主线，每一步之后做「三看」。

**三看**（每个动作之后都做，一个不能省）：
1. **看下游**：这个动作产生的东西，在哪几个页面应该出现？逐个打开核对
2. **看刷新**：F5，**再等 60 秒**，还在吗
3. **看换人**：换个角色登录，他看得到吗？数字一样吗

| 角色 | 他的一天 |
|---|---|
| 销售 | 工作台看今天要跟谁 → 线索管理挑一条 → 转客户 → 建合同（用「新建客户」）→ 看回款节点 → 情报雷达找新机会 |
| 总助 | 工作台看全公司 → 合同管理从合同立项、指定负责人和交期 → 项目管理看谁手上重 → 不符合项管理看有没有要整改的 → 战略管理让 AI 读一次数字 |
| 顾问 | 工作台看我今天的活 → 我的任务逐条做 → 项目管理点开项目、改任务状态（**「进行中」和「跳过」各试一次，填跳过原因，刷新看还在不在**）→ 记工作日志 → 知识中心找模板 |
| 财务 | 工作台看现金 → 回款概览标一笔已收 → 看逾期那几笔 → 顾问结算 → 导出 |
| 总经理 | 工作台六个视角各切一次 → 营收 → 项目管理看全公司 → 战略管理 → AI 中心 |
| 系统管理员 | 员工账号建号、分角色、改角色、停用 → 登录审计 → 试着删一个经手过记录的账号（**应该删不掉**）→ AI 中心看用量 |

顾问那条里「进行中／跳过」和总助那条里「战略 AI」，
2026-09-15 都刚修过 —— **你要验它们是真的修好了**。

# 第四部分：全局的几样

这几样不属于任何单页，但每一页都受影响：

1. **侧边栏**：每个角色看到的菜单项，和总表第一节对得上吗？
   多出来的、少掉的都要报。
2. **顶部**：全局搜索搜一个客户名，六个角色分别能搜到什么？
   （权限外的数据不该被搜出来）
3. **铃铛**：三档分组（今天要做 / 之后 / 待安排）显示对吗？
   点一条进得去吗？标记已读之后刷新还是已读吗？
4. **账号菜单**：切换视角、我的登录设备、修改密码、退出登录，
   各点一次。**退出登录要确认真的退到登录页**（这条 2026-09-15 刚修）。
5. **新手引导**：用全新账号第一次登录，引导出现吗？
   能跳过吗？跳过之后还能再打开吗？
6. **浏览器后退键**：在各页面按后退会怎样（HashRouter，
   真实地址都是 `/`，路由在 `#` 后面）。
7. **详情页直接刷新**：带 hash 的地址刷新，还能打开吗。

写到 `docs/逐页清点报告.md`：

```markdown

发现 __ 个挡住上线的问题，__ 个别扭但能绕过，__ 个小瑕疵。
最该先修的是：……

## 一、角色 × 页面（85 格全表）
（把总表第一节的表抄过来，每格填实际结果。
  一个格子都不许留空 —— 没测的写「未测 + 为什么」。）

## 二、可点文案（357 条）
每页一张表。全对的页面可以写「N 条全部正常」，
但**有问题的必须逐条列出**。

## 三、六个角色的工作流
每条一张步骤表，标清三看结果。

## 四、全局七项
逐项写结论。

## 五、发现的问题（按严重程度）
### 挡住上线
### 能绕过但很别扭
### 小瑕疵

每条写：
- **症状**（用人的话，不写代码）
- **复现步骤**（1. 2. 3.，别人照着能重现）
- **哪个角色、哪一页、哪个按钮**
- **影响**：谁会干不下去 / 会看错什么

## 六、我建的账号和造的数据
- 账号：uat-xxx ×6（已删 / 已停用）
- 数据：UAT- 开头 N 条，分别是……

## 七、没测到的和为什么
诚实写。**宁可写「这 8 格没测，因为 X」，也不要假装测过。**
```

## 硬性约束

1. **不许改业务代码。** 只清点、只出报告。
2. **结论必须来自界面。** 代码只用来解释你已经看到的现象。
3. **每条发现要有复现步骤。**
4. **不许跑破坏性命令。** 不重置、不 `git checkout .`、
   不用 `pkill -f "server/app.js"` 这种模式杀进程
   （文件名会撞车，误杀过别人的开发服务器）。要停进程用 PID。
5. **3000/3001 可能被别的项目占用**，起服务前先
   `lsof -nP -iTCP:3000 -sTCP:LISTEN` 看清是谁的。
6. **烧 token 的动作各跑一次就够**（合同识别、情报抓取、战略分析、AI 助手）。
7. **密码和密钥不进报告、不进仓库、不进对话。**

## 量太大怎么办

85 格 + 357 条确实多。如果一轮跑不完，**按这个顺序**，
做完一段就把报告写一段（不要攒到最后）：

1. 第一部分的 `—` 格子（权限漏洞，最危险，格子最少）
2. 第三部分的顾问和总助工作流（人最多、用得最频）
3. 第一部分的 `✅` 格子
4. 第四部分全局七项
5. 第二部分 357 条文案（最耗时，放最后）

**每做完一段就在报告里标清「这一段做完了」**，
这样中断了也知道从哪接。
