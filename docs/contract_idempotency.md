# 合同录入幂等与项目负责人规则

## 目标
- 杜绝同一合同被重复录入导致的数据污染与重复立项
- 明确“录入合同并同步生成项目”时的项目负责人（manager）默认策略与可调整入口

## 术语
- 合同唯一键（Unique Key）
  - 优先：`contractNo`（合同编号）
  - 兜底：指纹键（Fingerprint），由关键字段规范化后拼接生成
- 立项幂等（Project Idempotency）
  - 以 `Project.contractRef` 与合同关联，保证同一合同最多 1 个活跃交付项目

## 合同幂等策略（强幂等）
### 唯一键规则
1. 若 `contractNo` 非空：使用 `contractNo` 作为合同唯一键（大小写/空白规范化后比较）
2. 若 `contractNo` 为空：使用指纹键作为唯一键
   - 指纹键字段：`customerName + title + signDate + amount`
   - 规范化规则：
     - 文本：去首尾空白、连续空白压缩、统一全角空格
     - 日期：要求 `YYYY-MM-DD`（无法解析则按原值）
     - 金额：仅保留数字与小数点

### 行为
- 命中相同唯一键：拒绝新增合同，返回已有合同 id，并提示用户打开已有记录

## 立项幂等策略（合同 -> 项目）
### 关联规则
- 交付项目的 `contractRef` 使用 `contract.id`（若历史数据使用 `contractNo`，查询时同时兼容）

### 行为
- 当“同步生成项目”启用时：
  - 若已存在 `contractRef == contract.id` 的活跃项目：不重复创建，返回已有项目 id
  - 否则：创建交付项目

## 项目负责人（manager）默认策略
### 默认策略（推荐）
- 合同同步创建交付项目时：`manager = '待指派'`
- 后台在“项目管理”中指派负责人（仅老板/交付负责人可操作）

### 可选策略（效率优先）
- 合同同步创建交付项目时：`manager = 当前操作人`
- 仍保留后台改派入口与权限控制

## 权限要求
- 合同录入：需要 `CONTRACT_CREATE`
- 指派/改派项目负责人：需要 `PROJECT_ASSIGN_MANAGER`

## 回滚策略
- 若出现误拦截或历史数据不完整：
  - 降级为“仅立项幂等”（允许重复合同，但禁止重复立项）
  - 或临时关闭“指纹键兜底”，仅以 `contractNo` 去重
