# 整改任务持久化修复

问题：前端新增/更新整改时仅调用 setProjects 修改内存里的关联任务，整改记录会同步到数据库，但项目页面刷新从 projects 关系表加载时，任务可能消失或仍为旧状态。

修复：在带基线保护的 `/api/state/sync` 保存整改数据时，将关联任务更新纳入同一 PostgreSQL 事务。仅处理发生变化的整改记录，锁定关联项目后读取当前任务数组，增改删对应任务并重算进度；保留其他任务、项目字段和任务扩展字段。支持关闭整改、转移项目、删除及幂等重试。关联目标不存在或新链接占用其他任务编号时拒绝保存。

验证范围：隔离测试库中经 HTTP 保存整改，查询项目接口及数据库回读；覆盖新增、关闭、重试、转移、删除、无效目标拒绝、数据库写入失败后两边一起回滚。测试文件 `tests/audit-task-persistence.test.js`。

限制：本次保护针对带基线的整改同步路径；不会自动修复历史缺失任务，不代表其他项目整批写入接口获得并发保护。四岗位实际浏览器验收、历史数据核对、HTTPS 和真实项目归属仍待完成。

验证结果：全量回归 488/488 通过，0 失败、0 跳过；类型检查与前端构建通过。证据日志：`.artifacts/audit-full-tests-20260911.log`、`.artifacts/audit-build-20260911.log`。

已发布版本：`2c4c60a-20260910T235057Z`。服务、首页、静态资源、认证数据库及未登录拦截检查通过；发布日志 `.artifacts/audit-deploy-20260911.log`。未新增生产测试业务数据。
