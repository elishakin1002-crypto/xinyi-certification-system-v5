## 二、过程中修掉的两个真 bug

### bug 1：裸 `SC` / `QS` 正则会误判

```
「SCADA 系统」 → 食品生产许可   ❌
「QSA 审核」   → 食品相关产品   ❌
```

缩写恰恰是最容易嵌在别的词里的东西。已改成卡词边界 `(^|[^A-Za-z])SC([^A-Za-z]|$)`。

> 顺带核实：「温州优堡五金制品有限公司」被判成食品生产许可**不是误判** ——
> 它的服务项名称真的写着「SC 食品生产许可」。五金厂做食品许可这件事本身有点奇怪，
> 系统读对了，数据对不对你自己判断。

### bug 2：安全提示说了谎

脚本标题按 `DATABASE_URL` 里有没有 `localhost` 判断环境。
**而在服务器上跑时，数据库就是本机的** —— 于是它动着生产，标题却打出「本机开发库」。

**安全提示说谎比没有提示更糟**：它会让人放心地按下 `--apply`。
已改成按**意图**判断（有没有加 `--allow-prod`）。

## 三、建议负责人已接进建项目表单

### 实测（本地，真实数据）

**第一步：只输项目名**

```
优福包装 QS 食品相关产品生产许可续期
                    ↓
建议：商春姿   手上 0 个在制          [采纳]
  · 「食品相关产品」是他的方向
备选：陈诗蕾（手上 0 个）
```

**第二步：选上客户 —— 这时最强的信号才进来**

```
建议：商春姿   手上 0 个在制          [采纳]
  · 「食品相关产品」是他的方向
  · 这家客户的「食品相关产品」以前就是他做的     ← 防抢客户的锚
  · 他做过包装印刷行业的客户
备选：陈诗蕾（手上 0 个）
```

**第三步：点「采纳」** → 负责人变成商春姿，**建议条自动消失**
（已经选对了还杵一条建议是纯噪音，而噪音多了真正该看的那次也会被划过去）。

### 回答你的原问题

> 「在输入项目名称和项目的服务内容时根据少量信息判断推荐吗？」

项目名只是**四个信号里最弱的那个**。真正起作用的是选上客户之后的
「这家客户的这类服务以前是谁做的」—— 上面第一步和第二步的差别就是它。

### 回填前后的对比（同一个场景，生产数据）

| | 回填前 | 回填后 |
|---|---|---|
| 优福包装食包续期 | 和「全新客户」结果**完全一样**（只有方向这一条理由） | 商春姿 **80 分** vs 陈诗蕾 24 分，带「以前就是他做的」 |

**这就是为什么必须先回填。** 没有历史，最强的信号是死的。

### 三条交互设计

1. **建议只在和当前选择不一致时出现** —— 已经选对了就不说话
2. **理由必须写出来** —— 没有理由的建议不叫建议，叫猜；
   而且理由摆在那儿，「为什么不是我」当场就有答案，这才是抢客户的真正解法
3. **走第三方时不推荐任何人**，直接说「记得写清合作方和对接人」
