# 前端一致性横扫报告（2026-09-15）

## 一、必须上线前修（会让人看到互相矛盾的数字，或功能悄悄不生效）

### 1. 任务点成“进行中”或“已跳过”后，经过项目接口会被悄悄改回“待处理”
- **在哪看到**：所有角色 / 我的任务、项目管理 / 任务状态按钮。
- **两边分别是什么**：前端把未完成任务分为 `Pending`、`InProgress`、`Skipped`，并明确把 `Skipped` 排除在未完成之外（`src/modules/taskFlow.ts:55-56`、`src/modules/taskFlow.ts:146`）；项目接口的 `normalizeTaskStatus` 只接受 `Pending`、`Completed`，其余值统一回退为 `Pending`（`server/app.js:1501-1503`），并在构造接口任务时实际调用（`server/app.js:1520`）。
- **真因**：同一个任务状态枚举在前端和项目接口各维护了一份，服务端白名单少了两个现行状态。
- **证据**：☑并排代码。具体是：`Projects.tsx:685` 会写入 `Skipped`，任务控件会写入 `InProgress`；接口归一化函数会把两者改为 `Pending`。
- **影响面**：我的任务、工作台“我今天的活”、逾期数、项目结项检查、跳过原因记录都会受影响。
- **建议怎么改**：任务状态使用一份共享枚举；接口必须原样支持全部现行状态，并加“写入后重新读取”回归测试。

### 2. 财务工作台同一屏两个“逾期”金额仍然不一致
- **在哪看到**：财务 / 工作台 / 顶部“逾期回款”和经营趋势下方“逾期未收合计”。
- **两边分别是什么**：顶部显示“¥59000.00”，下方显示“¥173,400”。
- **真因**：页面仍存在不同的逾期计算入口；顶部使用 `dayDiff(item.dueDate, now) < 0`（`pages/Dashboard.tsx:325-327`），其它位置使用统一的 `isReceivableOverdue`（`pages/Dashboard.tsx:599`、`pages/Dashboard.tsx:645`）。
- **证据**：☑跑过 ☑并排代码。具体是：2026-09-15 使用财务账号打开工作台，抄到上述两个数字。
- **影响面**：财务判断催收总额、经营趋势以及从卡片进入的明细口径。
- **建议怎么改**：所有逾期回款数字和列表只从 `isReceivableOverdue` 过滤后的同一数组派生。

### 3. “今天到期”的回款在工作台与回款概览里会得到不同状态
- **在哪看到**：财务 / 工作台与回款概览。
- **两边分别是什么**：统一术语函数用 `due < today`，今天到期不算逾期（`src/modules/glossary.ts:132-139`）；回款概览把日期零点转成时间戳后与当前时刻比较，今天零点一过即显示逾期（`pages/Finance.tsx:74-79`）。合同页的到期筛选又使用另一份时间戳算法（`pages/Contracts.tsx:1026-1031`）。
- **真因**：同一个“逾期回款”概念存在至少三份日期判据，“按自然日”与“按零点时刻”混用。
- **证据**：☑并排代码。具体是：同一天字符串在统一函数中 `due < today` 为 false，在回款页 `new Date(due).getTime() < Date.now()` 为 true。
- **影响面**：财务工作台、回款概览、合同列表的到期下钻。
- **建议怎么改**：统一到一个回款逾期函数，并明确“到期当天是否逾期”的业务口径。

### 4. “与我相关”的项目、合同和工作台采用三套不同归属判据
- **在哪看到**：咨询顾问、销售、总助 / 项目管理、合同管理、工作台。
- **两边分别是什么**：项目页认 `ownerUserId`、负责人姓名、服务项负责人 ID/姓名、任务负责人，以及无主项目（`pages/Projects.tsx:293-312`）；合同页只认合同 owner、关联项目 manager、任务 owner（`pages/Contracts.tsx:1059-1067`）；工作台只认项目 manager、任务 owner（`pages/Dashboard.tsx:330-340`）。
- **真因**：归属逻辑复制在页面里，没有共用 `isMineProject`；合同页和工作台漏掉 `ownerUserId`、服务项负责人，工作台还漏掉无主兜底。
- **证据**：☑并排代码。具体是：同一项目只有 `ownerUserId` 或只有服务项负责人时，项目页判“与我相关”，合同页和工作台判“不相关”。
- **影响面**：工作台项目数、合同“与我相关”、项目“与我相关”、相关卡片跳转后的列表。
- **建议怎么改**：将归属判定提到共享模块，并为项目、合同、工作台提供同一组构造数据用例。

### 5. 项目卡片写“有逾期任务的项目”，数字实际是“逾期任务条数”
- **在哪看到**：所有可进入项目管理的角色 / 项目管理 / 第四张统计卡。
- **两边分别是什么**：卡片标签为“有逾期任务的项目”（`pages/Projects.tsx:2635-2642`）；数值 `overviewStats.overdueTasks` 是逐项目累加逾期任务数量（`pages/Projects.tsx:561-563`）。点击后底部说明又显示“共 N 项逾期任务 · 涉及 M 个项目”（`pages/Projects.tsx:2685`）。
- **真因**：卡片从“项目数量”改为“任务数量”后只改了计算和下钻说明，未改标题。
- **证据**：☑并排代码。具体是：一个项目有 3 条逾期任务时卡片值为 3，但标题读成 3 个项目。
- **影响面**：总经理、总助、顾问对延期项目规模的判断。
- **建议怎么改**：卡片改名为“逾期任务”，或数值改为含逾期任务的项目去重数；二选一并与点击后的说明保持一致。

### 6. 情报“标记已分拣”点击并刷新后仍显示待处理
- **在哪看到**：总助 / 情报雷达 / “我国产品碳足迹标识认证试点取得积极成效”。
- **两边分别是什么**：操作前详情按钮为“标记已分拣”、列表状态为“待处理”；点击后刷新，详情仍为“标记已分拣”、状态仍为“待处理”。
- **真因**：本轮只报现象；未对业务代码作修改或推断。
- **证据**：☑跑过。具体是：2026-09-15 总助账号实际点击并刷新，界面无状态变化。
- **影响面**：所有情报分拣记录，用户无法确认操作是否保存。
- **建议怎么改**：先查请求响应与持久化结果，再让列表徽章从保存后的记录重新读取；补刷新后状态仍为已分拣的端到端用例。

### 7. 战略 AI 等待流程正常，但最终明确报模型不存在
- **在哪看到**：总助 / 战略管理 / “让 AI 读这些数字”。
- **两边分别是什么**：按钮显示“正在判断…30s”，下方显示“正在让模型读这些数字，通常 10-30 秒，最长等 60 秒。”；等待满 60 秒后显示“AI 模型配置有误（指定的模型不存在）。请联系系统管理员。”
- **真因**：界面给出的最终错误是指定模型不存在；本轮不进一步猜配置来源。
- **证据**：☑跑过。具体是：连续等待满 60 秒并记录最终原文。
- **影响面**：总助和总经理的战略经营判断无法生成。
- **建议怎么改**：核对实际可用模型与当前配置，并在上线自检中增加一次最小模型调用。

## 二、上线后再说（不影响判断，但迟早出事）

### 1. 合同附件的“我的合同”判据和合同列表也不是同一份
- **在哪看到**：咨询顾问 / 合同管理 / 合同列表与附件上传入口。
- **两边分别是什么**：附件入口只认合同 owner、项目 manager、任务 owner（`pages/Contracts.tsx:138-149`）；合同列表使用另一段几乎相同但独立维护的代码（`pages/Contracts.tsx:1059-1067`）；两处都漏了服务项负责人和项目 `ownerUserId`。
- **真因**：同页复制归属规则，且与项目页共享口径脱节。
- **证据**：☑并排代码。
- **影响面**：顾问可能看得到相关项目，但不能给对应合同补电子档案。
- **建议怎么改**：附件权限与列表范围调用同一归属函数；界面权限仅作提示，服务端仍独立校验。

### 2. “与我相关”是默认筛选，但顶部卡片刻意不跟状态和搜索，界面说明不够直观
- **在哪看到**：所有角色 / 项目管理 / 四张统计卡与筛选后的列表。
- **两边分别是什么**：卡片只跟范围和类别，不跟状态、搜索（`pages/Projects.tsx:537-565`）；列表同时跟范围、类别、状态、搜索（`pages/Projects.tsx:567-587`）。当前界面只说明筛选后的列表条数，没有直接写“顶部卡片不随状态和搜索变化”。
- **真因**：这是代码注释明确写出的产品选择，但用户在界面上看不到该口径说明。
- **证据**：☑并排代码。
- **影响面**：筛选某状态或搜索某客户后，用户容易把卡片数字当成当前结果统计。
- **建议怎么改**：在卡片区域加一句可见口径，或让卡片标题明确写“当前范围全部状态”。
