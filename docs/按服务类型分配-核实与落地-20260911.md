# 「客户按服务类型分配」—— 核实与落地

- **日期**：2026-09-11
- **起因**：金恩来 2026-09-10：「你这里说的谁负责哪些客户项目是什么意思？客户不是根据服务类型确定及分配的吗？」

---

## 一、你是对的，我问错了

我之前问「谁负责哪些客户」，是按**销售式归属**去问的 —— 好像这是一张只有你脑子里才有的对照表。

但你们不是这么分的。**是按服务类型分的**，花名册那一栏写得清清楚楚：

| 姓名 | 岗位职责 | 服务方向 |
|---|---|---|
| 黄佳佳 | 主要做食品厂的 SC 认证 | 食品生产许可 |
| 商春姿 | **食包**咨询、台账检验、设备校准、工商代理 | 食品相关产品 |
| 黄邦煜 | 体系认证 | 体系认证 |
| 梁杰 | 体系认证、企业验厂、绿色产品 | 体系认证 / 验厂 |
| 郑园园 | 省科、国科、企业技术中心申报、残保金、专利 | 科技申报 / 知识产权 |
| 林元波 | 职业病危害因素检测 + 职业病体检 | 职业卫生 |
| 曾瑞锨 | 安全类项目、技改项目、信息类体系认证 | 安全生产 / 科技申报 |
| 陈诗蕾 | QS 咨询、台账 | 食品相关产品 / 台账指导 |
| 温婵然 | 食包台账、安全台账、职业卫生台账、文化台账 | 台账指导 |

**这条规则比「谁跟谁」好得多，因为它是可推导的** —— 服务类型定了，负责人就定了，
不需要任何人去维护一张会过期的对照表。

所以正确的问题不是「你告诉我谁负责谁」，而是 **「系统里存没存服务类型」**。

## 二、存了，但系统推不出来

服务类型确实存着，在三个地方：合同 `service_line`、客户 `last_project_type` / `next_opportunity`、
项目的服务项 `name`。生产实测 59 条文本。问题是：

### 问题一：自由文本，同一个服务好几种写法

```
SC食品生产许可证                          ← 同一件事
SC 食品生产许可                            ← 字符串不等

QS 食品相关产品生产许可证认证咨询服务      ← 同一件事
QS 食品相关产品生产许可                    ← 字符串不等
```

10 份合同，**10 种写法**。按字符串比较，「同服务类型做过」永远只有一单。

### 问题二：服务项名称大部分根本不是服务名

```
浙江博峰数字科技有限公司 咨询服务合同书
温州铸鼎机械有限公司 认证到期挖角跟进
平阳县新锦油茶种植专业合作社 咨询服务合同书
```

根因：默认服务项是拿**项目名**命名的（`buildDefaultServiceItem`），
于是真正的服务名被淹没在一堆项目名里。59 条里有 18 条是这种。

### 问题三：线索的目标认证 454 / 455 是空的

线索侧完全没有服务类型信息，所以线索阶段用不上这条规则。

### 问题四：`project_type` 不是服务类型

全库 30 个项目都是 `Self-Operated` —— 那是**自营 / 外包**，和服务类型是两回事。
这个字段名容易误导。

## 三、解法：和行业归类同一套做法

`src/modules/industry.ts` 解决的是「180 个工商行业值 → 12 个信义大类」。
这里是同一个问题的另一面：「N 种服务写法 → 一组信义实际分工的大类」。

新增 **`src/modules/serviceLine.ts`**：

- **关键词规则 + 顺序即优先级**，不用枚举映射
  （服务名是开放集合，明天就可能冒出新写法；枚举表永远补不完，
  补不上的会静默落进「其他」然后没人知道）
- 大类**不是我拍的**，是照花名册的岗位职责倒推 —— **有人专门做的才配当一个大类**

### 12 个服务大类

| 大类 | 建议负责人 | 备选 |
|---|---|---|
| 体系认证 | 黄邦煜 | 梁杰 |
| 食品生产许可 | 黄佳佳 | — |
| 食品相关产品（食包） | 商春姿 | 陈诗蕾 |
| 验厂 | 梁杰 | — |
| 科技申报 | 郑园园 | 曾瑞锨 |
| 职业卫生 | 林元波 | — |
| 安全生产 | 曾瑞锨 | — |
| 台账指导 | 温婵然 | 陈诗蕾、商春姿 |
| 计量校准 | 商春姿 | — |
| 工商代理 | 商春姿 | — |
| 知识产权 | 郑园园 | — |
| 其他许可 | **无人对应** | — |

### 三个必须靠规则顺序才分得对的地方

1. **QS 必须排在 SC 前面** —— 「食品相关产品生产许可」既含「食品」也含「生产许可」，
   按 SC 的关键词会命中，但它是食包（商春姿）不是食品厂（黄佳佳）。**归错就是派错人。**
2. **体系认证排在所有食品/安全规则前面** —— ISO 22000 叫「食品安全管理体系」、
   ISO 45001 叫「职业健康安全管理体系」，名字里带着别的大类的关键词，但它们都是体系认证。
3. **项目名不参与归类** —— 「XX公司 咨询服务合同书」会命中一堆规则，归出来纯属噪音。

## 四、实测覆盖率

拿生产库全部 59 条服务文本跑：

```
全部文本 59 条 → 其中像服务名的 41 条
                （其余 18 条是项目名/合同名，本来就不该参与归类）

服务名归类覆盖率：90%  (37/41)
```

| 大类 | 条数 | 建议负责人 |
|---|---|---|
| 体系认证 | 14 | 黄邦煜 |
| 工商代理 | 7 | 商春姿 |
| 食品生产许可 | 5 | 黄佳佳 |
| 食品相关产品 | 4 | 商春姿 |
| 其他许可 | 3 | **无人对应** |
| 科技申报 | 3 | 郑园园 |
| 验厂 | 1 | 梁杰 |
| 未分类 | 4 | — |

剩下那 4 条未分类是 **「待评估」「政策窗口/复评」** —— 那本来就不是服务名，
是「下一步机会」栏里的备注。**所以真实服务名基本全部归对了。**

> ⚠️ 一个过程教训：第一次跑覆盖率是 **51%**，看起来规则只覆盖了一半，
> 差点去大改规则。拆开才发现 30 条「未分类」里有 26 条根本不是服务名。
> **分母错了，结论就会错，而且错在「要大改」这个最费事的方向。**
> 所以模块里单独做了 `looksLikeServiceName()`，把「不是服务名」和
> 「是服务名但认不出」分开。

## 五、和行业归类的一个关键区别

| | 行业归类 | 服务归类 |
|---|---|---|
| 归错的代价 | 小 —— 检索时多看/少看几篇资料 | **大 —— 活派给不对的人** |
| 拿不准时 | 宁可归粗一点 | **一律落「未分类」，不硬猜** |
| 无对应人时 | 不适用 | **如实说「没人对应」，不就近指派** |

所以 `suggestOwnerByService()` 认不出服务类型时返回 `null`，
界面上要显式提示人工指定，**不能静默吞掉**。

## 六、需要你定的两件事

### 1. 医疗器械、饲料添加剂这类许可谁做？

花名册里**没有任何人的岗位职责覆盖**这一类，但生产库里有 3 条：

- 饲料添加剂和饲料生产许可证咨询服务
- 医疗器械经营/生产许可证

系统现在如实报「无人对应，需人工指定」。要么告诉我归谁，要么确认这类活是外包/个案处理。

### 2. 「建议负责人」要不要自动派活？

我做成了**建议**而不是自动执行：系统给出建议负责人，最终由人确认。

理由：一个人休假、手上活满了、客户点名要谁 —— 这些系统都不知道。
直接自动派活会让人觉得系统在替他做主，然后绕过系统。

如果你觉得应该直接自动派，告诉我，改成自动 + 可手工覆盖也可以。
