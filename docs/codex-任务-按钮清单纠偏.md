# 任务：把「357 条可点文案」这份清单修准

## 背景

`docs/上线前逐页清点-总表.md` 第二节那 357 条，是 Claude 用正则从
各页面的 `<button>` 和三元表达式里抽出来的。**抽得不准**：
你在逐页清点时已经发现至少 3 条（「我的交付状态」「交付风险」「工作沉淀」）
其实是板块标题，根本点不了。

一份混着假条目的清单，会让人把时间花在不存在的按钮上，
也会让「还剩多少没测」这个数字失真。

## 你要做的

**只读代码，不要开浏览器**（无头模式下你的浏览器要人当场批准，会卡住）。

1. 重新扫 `pages/` 下所有 `.tsx`，抽出**真正可点击**的元素文案：
   - `<button>` 的文本
   - 带 `onClick` 的其它元素（`<a>`、`<div role="button">` 等）
   - 排除：纯标题、`<label>`、统计卡的 label（除非那张卡自己带 onClick）
2. 对每一条标注它属于哪个页面、大致在页面的哪个区域
   （头部/筛选区/列表行/弹窗/详情），方便逐个找。
3. 把结果写成 `docs/可点元素清单.md`，格式自己定，但要满足：
   - 按页面分组，每组给出条数
   - 总数放最前面
   - **单独列一节「原 357 条里被判定为不可点的」**，逐条说明为什么
     （是标题？是 label？是死代码？），这样 Claude 能核对你的判断
4. 往 `docs/协作日志.md` 追加一行说明你做完了、新的总数是多少。

## 硬要求

- **不许改任何业务代码**，只新增 `docs/可点元素清单.md` 和追加协作日志
- 不许开浏览器、不许起服务、不许跑破坏性命令
- 判断不了的条目放进「存疑」一节，不要硬塞进任何一边
- 中文，说人话
