# 一、这一轮的验收结构

按发布验收的标准分六层，**从粗到细**，前一层不通过就不必往下走：

| 层 | 查什么 | 不通过的后果 |
|---|---|---|
| L1 冒烟 | 六个角色能不能登录、能不能打开自己该看的页 | 系统根本不能用 |
| L2 权限 | 每个角色 × 每个页面 × 每个动作，该能的能、该拦的拦 | 有人看到不该看的钱 |
| L3 功能 | 318 个可点入口，逐个点，看做没做它承诺的事 | 点了没反应 |
| L4 数据 | 每个面板的每个字段，和库里真相对账 | 数字骗人 |
| L5 联动 | 六条业务链路端到端，做完一步去下游看 | 断链 |
| L6 边界 | 空/极值/超长/特殊字符/并发/刷新/重登 | 上线后被真实数据打穿 |

## 缺陷分级（报告里每条都要标）

- **P0 阻断** —— 核心流程走不下去，或者钱/权限出错。**不修不能上线。**
- **P1 严重** —— 能绕过但很别扭，或者数字会误导人。
- **P2 一般** —— 体验问题，不影响判断。
- **P3 轻微** —— 文案、间距这类。

## 出口标准（什么算验收通过）

1. P0 = 0
2. P1 全部有结论（要么修了，要么老板明确接受并记进上线后待办）
3. L1～L5 覆盖率 100%（每一格都有实际结果，"未测"也算没通过）
4. L6 至少覆盖每个主要对象（客户/合同/项目/任务/应收）各一轮

# 二、每一层具体怎么做

## L1 冒烟（最先做，10 分钟）

六个角色各登录一次，各打开一次工作台。任何一个进不去，**立刻停下来报**，
不要继续往下 —— 后面所有结论都会建立在坏掉的地基上。

## L2 权限矩阵

对照 `docs/上线前逐页清点-总表.md` 第一节那 85 格。**该进不去的那些格子
是重点**，因为最容易被跳过：菜单里看不见 ≠ 地址进不去。

每个「不该进」的格子，在地址栏直接敲（HashRouter，形如
`http://localhost:3000/#/finance`），记录：
1. 被挡住了吗？
2. 挡的时候说了什么？（应该显示「打不开「/finance」，已回到工作台。
   这个模块没有对你开放…」）
3. 挡住之后有没有出口？

能进去 = **P0**，直接进报告第一档。

这个项目权限有**三份定义**（`ROLE_PERMISSIONS` 管菜单、`ROLE_CAPABILITIES`
管动作、服务端还有一份解析出来的），只改一处的典型症状是
「菜单看得见但每个请求都 403」或「菜单看不见但地址能进」。

动作级也要测：每个角色在每个页面，把**会改数据的按钮**点一次
（在 `UAT-` 数据上），看是被前端拦、被后端 403、还是真的做了。

## L3 功能：318 个可点入口逐个点

用你自己做的 `docs/可点元素清单.md`。每条记录：

| 编号 | 页面/区域 | 文案 | 点了有反应吗 | 反应对吗 | 报错 | 分级 |
|---|---|---|---|---|---|---|

「反应对吗」问三句：
1. **它做了它说要做的事吗？**（「导出」真下载了文件吗？文件打开对吗？
   「重置筛选」真的全部重置了吗？）
2. **做完之后人知道下一步去哪吗？** 成功提示只说「操作成功」不合格。
3. **点两下会怎样？** 连点三下会不会建出三条。

### 这个项目已经出过的「点了没反应」形态，每一条都要专门盯

- **点了界面没变，但后端其实成功了**（徽章没跟着状态走）
- **点了界面变了，刷新又变回去**（轮询把人的决定盖了 —— 情报雷达出过）
- **点了什么都没发生**，控制台一行 warn（请求 404 被吞掉）
- **按钮切到的筛选，列表根本不支持**（点了等于没点，还高亮着）
- **按钮的 tooltip 承诺了一件事，代码做的是另一件**（全局搜索出过）

所以**每个会改数据的按钮，点完都要刷新一次再看**；情报雷达那页
**再等 60 秒看一次**（那里有 10 分钟轮询）。

### 危险按钮

删除、归档、停用、批量、重置、导入 —— 只在 `UAT-` 数据上点。
特别验一条：**试着删一个经手过记录的账号，应该删不掉**，
而且提示要说清为什么、该用什么代替。删得掉 = **P0**。

## L4 数据：每个字段和库里对账

这一层是**最容易漏、也最能暴露问题**的一层。做法：

1. 打开一个页面，把顶部每张卡的**名字和数字**抄下来
2. 直接查库（用 `dotenv` + pg）算出同一个口径的真值
3. 逐个对

对不上的，先别急着报 bug —— 先确认是**口径不同**还是**算错了**。
口径不同也要报：界面上没说清口径，人一样会看错。

### 已经定死的口径，照着核

- 今天到期的任务和回款，**都不算逾期**
- 没填日期的，**不算逾期**（没约定就没有迟到）
- 已跳过的任务算了结，**不算未完成**
- 已结项项目里的残留任务，**不进「我今天的活」**
- 客户总数 = **建了档就算**
- 没填日期的提醒进「待安排」，**不进「今天要做」**
- 金额：库里存「分」，但仓储层已经 ÷100，**前端拿到的是「元」**
- 项目管理四张卡**全部数项目**，不数任务

### 同一个词跨页面对一遍

| 词 | 在哪几页出现 | 各是多少 | 应该相等吗 | 实际 |
|---|---|---|---|---|
| 逾期任务 | 工作台 / 我的任务 / 项目管理 | | | |
| 逾期回款 | 工作台 / 财务 / 合同管理 | | | |
| 进行中项目 | 工作台 / 项目管理 | | | |
| 客户总数 | 工作台 / 客户管理 | | | |
| 与我相关 | 项目 / 合同 / 客户 / 线索 | | | |

**不相等而又叫同一个名字的，一律 P1 起步。**

### 同一条数据跨角色看一遍

挑三条真实数据（客户、合同、项目各一），六个角色分别登录，记录每人看到什么：
看得见吗？金额显示什么（顾问按设计看不到，应显示 `¥***`）？能改吗？

**「某个角色看不到」不一定是 bug，但必须说得出为什么。**
说不出理由的报出来 —— 「合同管理里有、项目管理里没有」就是这样被发现的。

## L5 联动：六条链路端到端

每一步做完执行「**三看**」，一个都不能省：

1. **看下游**：这个动作产生的东西，在哪几个页面应该出现？逐个打开核对
   （至少：对应管理页、工作台卡片数字、我的任务、提醒铃铛、
   相关客户/合同的详情页）
2. **看刷新**：F5，**再等 60 秒**，还在吗
3. **看换人**：换个角色登录，他看得到吗？数字一样吗？

| # | 链路 | 关键检查点 |
|---|---|---|
| 1 | 线索 → 客户 → 合同 → 立项 → 任务 → 结项 → 回款 | 主干，走不通别的都白搭 |
| 2 | 合同识别（AI 一次建合同+客户+项目） | 建出来的项目有没有负责人？换个角色看得到吗？（这条出过事）|
| 3 | 证书到期 → 续证跟进 | 提醒在谁的铃铛里？点进去有没有出口？|
| 4 | 情报 → 分拣 → 转线索 | 点完刷新、**再等 60 秒**（这条出过事）|
| 5 | 不符合项 → 整改任务 → 关闭 | 「新增/关闭」两个数字怎么动的 |
| 6 | 建号 → 分角色 → 改角色 → 停用 → 试删 | 经手过记录的账号必须删不掉 |

链路 1 里有几个专门要试的：
- 建合同时**不选已有客户**，用「新建客户」，看公司名有没有自动带过来
- 一笔应收**不填到期日**，看会不会被算成逾期
- 一笔应收**到期日填今天**，看算不算逾期（口径：不算）
- 任务点「进行中」、另一条点「跳过」并填原因，**刷新看还在不在**（这条出过事）
- 顾问看得到合同金额吗（设计上看不到，应显示 `¥***`）

## L6 边界

每种主要对象（客户/合同/项目/任务/应收）各过一轮：

- **空**：一条都没有时页面长什么样，有没有告诉人怎么开始
- **极值**：金额 0 / 很大；日期今天 / 去年 / 留空
- **超长**：公司名 100 字、备注 2000 字 —— 会不会撑破布局
- **特殊字符**：名字里带 `<script>`、引号、emoji、换行
- **重复**：同名客户建两次，有没有查重提示
- **并发**：提交按钮连点三下会不会建出三条；两个窗口同时改同一条
- **持久性**：做动作 → 刷新 → 退出重登 → **换隐身窗口登录**，还在吗
  （第三步专抓「只存在这台浏览器里」的假保存；
  跑完可以用 `npm run checkup:consistency` 对账两处存储）
- **手机端**：375px 下走一遍链路 1，看表格溢出、按钮被挤出屏幕、弹窗关不掉
- **中断**：弹窗填一半关掉再打开；浏览器后退键；详情页直接刷新

# 四、硬性约束

1. **不许改业务代码。** 只验收、只出报告。发现要改的写进缺陷清单。
2. **结论必须来自界面。** 代码只用来解释你已经看到的现象，
   不许用读代码代替实跑 —— 上一轮就是这么漏掉三个问题的。
3. **每条缺陷必须有复现步骤。**「感觉不对」不算。
4. **不确定就写不确定。** 你自己总结过一句很准的话：
   「**结论的确定程度不能超过证据**」。照这句做。
5. **不许跑破坏性命令。** 不删非你造的数据、不重置、不 `git checkout .`、
   不用 `pkill -f "server/app.js"` 这种模式杀进程（文件名会撞车，
   误杀过别人的开发服务器）。要停进程用 PID。
6. **密码和密钥不进报告、不进仓库、不进对话。**
7. **烧 token 的动作各跑一次就够**（合同识别、情报抓取、战略分析、AI 助手）。
8. **每完成一层**往 `docs/协作日志.md` 追加一行中文进度，给老板看的。
