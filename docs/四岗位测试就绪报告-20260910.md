## 一句话结论

四个岗位的账号、权限、可见范围**都已验收通过，功能这一侧可以开测**。
拦路的不是代码，是**生产库里几乎没有东西「有主」**：30 个项目只有 3 个的负责人是真人，
455 条线索一条归属都没有。这种状态下叫人来测，收回来的不是缺陷，是误判。

## 三、验收结果

每个岗位跑一遍，回答四个问题：登得进来吗 · 该看的看得见吗 · 打开有没有东西 · 越权是被干净拒绝还是把服务器搞崩。

### ✅ 通过：登录与角色识别

四人全部登录成功，角色分别识别为 MANAGER 与 CONSULTANT ×3。

### ✅ 通过：权限边界

| 请求 | 顾问（3 人） | 总助 |
|---|---|---|
| `/api/projects` | 200 | 200 |
| `/api/customers` | 200 | 200 |
| `/api/leads` | 200 | 200 |
| `/api/contracts` | 200 | 200 |
| `/api/auth/users` | **403** | 200（要核对花名册） |
| `/api/ai/usage` | **403** | **403** |
| `/api/auth/audit-logs` | **403** | — |

**没有一个返回 500。** 403 是「设计如此」，500 是「你没想到有人会这么点」——
后者往往还伴随脏数据。路由守卫覆盖 14/14 个页面。

### ✅ 通过：空状态说人话

黄佳佳名下 27 条任务全部已完成，而「我的任务」默认筛「未完成」→ 她打开是 **0 条**。

页面没有留白，写的是：

> 你名下没有未完成的任务
> 要么确实做完了，要么任务还没派到你名下 —— 去项目里看看，或者问一下项目负责人。

并配了一条样例行说明这一行长什么样。**这不是缺陷。**

但**我自己的测试差点放过去**：第一版判据数的是任务总数（27，绿灯），
真人点进去看到的却是 0 条。改成数「未完成」后才暴露。判据已修正。

### ⚠️ 待补：专业方向系统里没存

10 位顾问的 `position_tags` **全都是「咨询师」**，
食品认证 / 食包 / 体系认证这些方向只存在于花名册的 Excel 里。

后果：
- 派活时系统帮不上忙，不知道谁擅长什么
- 「同行业做过就能复用」认不出谁做过食品

这次的方向对应是我照 Excel 手工对上的。

## 四、开测前必须补：生产数据没有「主」

以下为**生产库实测**（2026-09-10）。不是功能缺陷，是数据没配齐 —— 但后果一样：人打开就是一片空白。

| 指标 | 实测 | 达标率 |
|---|---|---|
| 项目负责人是真人 | 3 / 30 | 10% |
| 任务负责人是真人 | 9 / 132 | 6.8% |
| 客户有归属人 | 0 / 11 | **0%** |
| 线索有归属人 | 0 / 455 | **0%** |
| 客户有证书到期日 | 0 / 11 | **0%** |
| 合同有归属人 | 12 / 12 | 100% ✅ |

### 🔴 阻断：总助的核心卡片列的是占位名

「谁手上活多少」是李智薇派活前要看的那张表，现在列出来的是：

```
销售 / 咨询      8 个项目
待指派           5 个项目
项目经理         3 个项目
系统管理员       1 个项目
```

**没有一个是真人。** 她照着这张表派不了活。

### 🔴 阻断：证书到期日一个都没填

「排跟进提醒」（到期前 30 / 15 / 7 天）唯一的输入就是到期日。
11 家客户一家都没填，**整条续期提醒链空转** —— 而续期是最稳的复购来源。

> 注：补到期日这个动作本身，此前还会引爆「自动建跟进项目」的老 bug
> （每 10 秒扫描一次，会凭空建项目并把线索锁成「已转化」）。那条已于 2026-09-09 拆掉并上线。

### ⚠️ 待补：本周日志覆盖率 0%

库里 47 条工作日志，**近 7 天 0 条**。所以工作台那个数字是对的，不是算错。
但它意味着「这周谁没记日志」这个指标在测试期没有参照 ——
要让四位同事在测试期真的记几天日志，这个指标才有意义。

### 为什么必须先补

同事打开系统看到空白，得出的结论是「这系统没东西」，然后再也不会认真点第二遍。
**这种测试比不测更糟 —— 它消耗的是信任，而真正的问题一个都没暴露出来。**

## 五、每人测什么

按各自岗位的真实动作设计，不是通用点击清单。每条都要能回答「这一步做完，下一步去哪」。

### 李智薇（总助）

1. 工作台 → 看「谁手上活多少」「卡住的事」
2. 项目管理 → 范围切「全公司」，找无人负责的项目并指派
3. 我的任务 → 切「我派出去的」，看派给别人的活做了没
4. 员工账号 → 核对花名册与系统是否一致

**要特别盯**：派活前那张表里出现的**是不是真人姓名**；指派负责人后，对方的「我的任务」是不是立刻出现这条。

### 黄佳佳（食品认证）

1. 我的任务 → 勾一条完成，回项目管理看进度是否同步
2. 客户管理 → 打开食品类客户，补一个证书到期日
3. 点「排跟进提醒」→ 看铃铛里是否出现 3 条
4. 不符合项 → 登记一条，填问题描述看是否推荐同类历史问题

**要特别盯**：补完到期日后提醒**排得出来吗**；**不该再自动冒出「认证到期跟进」项目**（这条 9/9 刚修）。

### 商春姿（食品包装）

1. 客户管理 → 行业筛「包装印刷」，确认 4 家都在
2. 项目详情 → 记一条工作日志，填工时
3. 知识中心 → 搜食包相关资料，看同行业内容能否检索到
4. 合同管理 → 打开一份合同，试 AI 识别

**要特别盯**：工时填 0.5 小时，**保存后回看还是不是 0.5**（这里历史上存成过 50）；
行业筛选是否把「包装装潢及其他印刷」正确归进「包装印刷」。

### 黄邦煜（体系认证）

1. 我的任务 → 6 条未完成，按已超期 / 今天 / 本周分栏核对
2. 项目管理 → 给任务设前置任务，看延期是否算出连带影响
3. 不符合项 → 走完「登记 → 整改 → 验证关闭」全链
4. 手机上再走一遍第 1、3 步

**要特别盯**：手机端右上角**头像点得到吗**（9/10 刚修）；任务状态改「进行中」后总助那边是否看得见。

### 四个人都要做的一件事

遇到任何看不懂的地方，**先点右上角问号里的「解释这一项」**。
如果它答不上来，**那本身就是要报的缺陷** —— 帮助答不上来比功能有 bug 更容易劝退人。

## 六、「头重脚轻」专项：已完成

金恩来 2026-09-08 提的问题 —— 聊一段改一段，系统会长成畸形比例。

| 维度 | 达标 |
|---|---|
| 空状态 | 14 / 14 |
| 样例行 | 14 / 14 |
| 本页详解 | 14 / 14 |
| 新手引导 | 14 / 14 |
| 手机端 | 14 / 14 |
| 测试覆盖 | 14 / 14 |

六个维度全满。剩下唯一的不均衡是**体量**：最厚的项目管理 3322 行，
是最薄的审计日志 217 行的 15.3 倍。

这一条判定为**合理** —— 审计日志本来就只是一张只读列表，不是「没人提过所以没做」。
体检脚本每次都会把这句话顶出来提醒复核，**保留这个提醒本身是有意的**。
