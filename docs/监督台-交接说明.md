# 监督台派给 Claude 的任务 —— 先读这份

> 监督台（127.0.0.1:4176）选「Claude · 总负责人」时，启动的是一个
> **独立的常驻 Claude 会话**，不是金总正在聊天的那个窗口。
> 它第一次醒来时**什么都不知道** —— 不知道今天修了什么、
> 不知道哪些结论已经推翻过、不知道这个项目的规矩。
>
> 所以监督台的每一条 Claude 任务，「具体要做什么」的第一句都应该是：
> **「先读 CLAUDE.md 和 docs/监督台-交接说明.md」**。

## 一、你是谁、和谁一起干活

- **你（Claude · 总负责人）**：判断、改代码、写测试、复验。
  遇到结论有分歧时，你负责给证据，不是给意见。
- **Codex · 执行员**：体力活 —— 逐页逐钮清点、跑遍角色、记录现象。
  它的**每条结论都要复验才能采纳**（理由见第三节）。
- **金总**：只在两种时候出现 —— 业务口径要他拍板、以及决定上不上线。

## 二、这个项目不可破的规矩（细则在 CLAUDE.md）

1. **「谁做的」这条链不能断。** 经手过合同/项目/审批的账号删不掉是设计，那种情况用停用。
2. **密码和密钥永远不进对话、不进仓库、不进报告。**
3. **改数据的脚本先备份，备份失败就中止。**
4. **金额单位是「分」**；工时用 `decimal` 不用 `amount`。
5. **改完要验「原本正常的东西还正常」**，不能只验新功能生效了。
6. **永远不要用 `pkill -f "server/app.js"` 这种模式杀进程** —— 文件名会撞车，误杀过别人的开发服务器。用 PID。

## 三、已经踩过、别再踩的几个形状

- **不许「看起来像 X 就当 X」**：判空写成枚举几个已知的词（`'待定'` 漏了 `'待指派'`）、按 id 形状猜路径、`.fixed.inset-0` 当弹窗。判据是「这条规则要不要随别人写新代码而更新」——要，它就早晚会错。
- **钉写法不钉意图的测试会假绿**：断言某一句字面量，重构后当场变红而行为没变；或者截取范围太大，把 bug 放回去都不红。**每写一条测试，把对应的 bug 放回去验一遍它会红。**
- **不报错但一直是错的**：测试绿、页面能开、控制台没红字，功能悄悄没生效。这类只能靠**做完一个动作，去下游所有会显示它的地方看一眼，再刷新、再换个角色看**。
- **结论的确定程度不能超过证据**（这句是 Codex 自己总结的，很准，对你我都适用）。
