## 一、计数口径与页面汇总

- 一条 = 一个源码中的点击位置。循环生成的一排按钮或一组数据卡算一个入口模板，文案栏列出固定选项；每条客户、每个项目等动态记录不展开计数。因此这个总数是定位清单条数，不是屏幕按钮个数，也不能直接拿来减原来的 357 得出“剩余未测数”。
- 同一按钮的展开／收起、处理中等状态写在同一条。相同文案在不同位置（如不同弹窗的取消、桌面与手机操作）分别记录，便于定位。
- 按 HTML 元素与事件判断：button、其它带 onClick 的节点，以及实际 href 链接；补查表单提交、祖先事件冒泡、上传框覆盖和 StatCard 的事件透传。图标按钮以方括号说明用途，并非臆造可见文案。
- 条件渲染和临时 disabled 不等于死代码；按正常可操作状态计入，并备注限制。SampleList／SampleRow 的演示数据拦截点击，不把示例内容当作真实入口。只阻止冒泡的容器不计数。
- 原生输入框、select、option、label 不在本次 button/onClick 口径内；原 357 中能选择的下拉项另列，绝不归为不可点。
- 范围是 pages/ 直接声明的点击位置（含 pages/dashboard 子目录）；components/、src/ui 内部另行声明的按钮不在本次数量内。为判定旧条目，已只读追查相关共享组件；这份表不是全应用控件总量。
- 工作台子组件按源码文件单列，避免把同一渲染模板按角色重复计数。角色文案在附注展开；标题配置文件显示 0，不代表该角色看板没有入口。
