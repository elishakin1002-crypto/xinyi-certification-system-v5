# 踩过的坑

这个项目已经踩过的坑。**动手前扫一遍，能省掉大半天。**

写它的原因：金恩来 2026-09-08 —— 「你踩的坑要写成文件，目的是我在用其他 AI
参与此项目时不会反复踩坑。」

---

## 怎么用这份文档

这里绝大多数坑有一个共同特征：**不报错，但一直是错的**。

测试是绿的、页面能打开、控制台没红字，只是功能悄悄没生效。
这类问题靠"跑一下看看"发现不了 —— 只能靠**知道它存在**。所以：

- 改到哪一块，先看那一节
- 每条格式统一：**症状 → 真因 → 怎么避免**
- 带日期的是真实发生过的，不是假想

## 一、权限

### 1. 权限有三份定义，改一处等于没改

**症状**：菜单看得见，但点进去每个请求都 403。或者反过来，接口能调，菜单没有。

**真因**：权限在三个地方定义 ——
- `constants.ts` 的 `ROLE_PERMISSIONS`：能看哪些**菜单**
- `constants.ts` 的 `ROLE_CAPABILITIES`：能做哪些**动作**
- `server/app.js` 的 `AUTH_ACTIONS_BY_ROLE`：服务端的动作校验

第三份原来是硬编码的一份副本。只改前面两处，就是「菜单出现了，请求全被拒」。

**怎么避免**：服务端那份现在从 `constants.ts` 解析（`server/authz/authorize.js`
的 `loadCapabilities`），并且**失败时 fail-closed**（只留 ADMIN/SYS_ADMIN）。
加新动作码时跑一遍 `tests/permissions-contract.test.js`。

### 2. `checkActionPermission('X', {})` 和不传第二个参数，结果**相反**

**症状**：2026-09-07「项目管理页里连新建项目的入口都没有了」。

**真因**：`{}` 是 truthy，于是走「这条数据是不是我的」判断，
而空对象不属于任何人 → 拒绝。不传则跳过归属判断 → 允许。

**怎么避免**：**新建类动作不传 context**。
`src/utils/actionPermissions.ts` 里现在用 `hasOwnershipInfo` 显式判断，
只有真的带了 manager/owner/tasks 才走 OWN 分支。

### 3. persona ↔ role 的映射曾有四份副本

**症状**：切到「销售视角」，看到的其实是总助的菜单。

**真因**：四处各写一份，其中一份把 `sales` 映到了 `MANAGER`。
另外 `normalizePersona` 的白名单漏了 `'manager'`，于是 `?persona=manager` 静默回退。

**怎么避免**：现在只有 `constants.ts` 里的 `ROLE_TO_PERSONA` 一份，
`PERSONA_TO_ROLE` 由它派生。**不要再手写第二份。**

### 4. 侧边栏的 `hasPermission` 绕过了视角预览

**症状**：预览成财务时，「项目交付」分组照样挂在那儿。

**真因**：判断只用了 `hasPermission`，没有 `inView`。

**怎么避免**：菜单显隐一律 `hasPermission(x) && inView(x)`。
动作按钮用 `checkActionPermission(...).allowed && actionInView(...)`。

## 二、数据与存储

### 5. 金额存的是「分」

**症状**：填 8000 元，直接跑 SQL 看到 `project_amount = 800000`，以为出了 100 倍的 bug。

**真因**：设计如此。`server/repos/_mapper.js` 里 `kind: 'amount'` 落库 ×100、读取 ÷100。

**怎么避免**：这是对的，别"修"它。但——

### 6. 工时不能用 `kind: 'amount'`

**症状**：0.5 小时被存成 50。走仓储读回来是对的（÷100），
所以**不报错、测试也可能是绿的**，只有直接跑 SQL 才看得出。

**真因**：工时不是钱，不该缩放。

**怎么避免**：非金额的小数用 `kind: 'decimal'`。
而「能用 SQL 统计工时」正是把工作日志搬进关系表的全部意义 —— 存错了这个意义就没了。

### 7. `contractRef` 的空值有两种长相

**症状**：2026-09-08 做「缺合同」提醒，功能看着在跑，**一条都没抓到**。

**真因**：`AppContext` 落库时 `p.contractRef || '无关联'` ——
于是「没有合同」在库里既可能是 `''` 也可能是字符串 `'无关联'`。
我第一版只判了空字符串。

**怎么避免**：用 `src/modules/projectCategory.ts` 的 `hasContract()`，不要自己判空。

### 8. PG 的 DATE 列不能用 `toISOString()` 取日期

**症状**：存 2026-10-01，读回来是 2026-09-30。「有效期到今天」的账号当天就登不进去。

**真因**：node-pg 把 DATE 解析成「本地时间零点」。东八区的 `2026-10-01 00:00+08:00`
转 UTC 是 `2026-09-30 16:00`，`toISOString().slice(0,10)` 就倒退一天。

**怎么避免**：用本地日期部件拼（见 `server/authStore.js` 的 `toDateOnly`）。
**测试里也一样** —— `tests/account-delegation.test.js` 就踩过，
表现是**只在半夜 0-8 点跑才失败**，白天怎么跑都是绿的。

## 三、前端 / 浏览器

### 9. nginx 的 `add_header`：子块一写自己的，父块的全失效

**症状**：在 `server` 块里加了三个安全响应头，首页一个都没有。

**真因**：nginx 规则 —— `location` 块里只要出现 `add_header`，
就丢弃从父块继承的全部 `add_header`。而首页走的 `location = /index.html`
里本来就有一条 `Cache-Control`。

**怎么避免**：需要全局生效的响应头，在**每个写了 add_header 的 location 里重写一遍**。
看着冗余，实际是必须的（`deploy/nginx-xinyi.conf` 里有注释）。

### 10. `position: fixed` 元素的 `offsetParent` 恒为 `null`

**症状**：三层帮助的「打开时先讲当前弹窗」整套逻辑**一次都没生效过**，
永远在讲整页。而且不报错。

**真因**：拿 `offsetParent !== null` 判断可见，而弹窗全是 fixed。
更妙的是手机版侧边栏因为祖先有 `transform`，fixed 退化成 absolute，
`offsetParent` 反而不是 null —— 判断结果正好全反了。

**怎么避免**：用 `getBoundingClientRect()` + 视口交集判断。见 `components/HelpHub.tsx`。

### 11. 「文档里最后一个」≠「盖在最上面那个」

**症状**：同上 —— AI 助手面板的类名里也有 `fixed inset-0`（手机上它确实铺满），
而它排在弹窗后面，于是「取最后一个」永远取到它。

**怎么避免**：按「铺满视口」筛，再按 z-index 取最上面。

### 12. 内容会长，屏幕不会 —— 弹窗和浮层必须限高

**症状**（踩过两次）：
- 新手引导：卡片高度用了拍脑袋的 260px，实际三四百像素，
  「下一步」被挤出屏幕底部，**引导卡死在第 3 步**。
- 建项目弹窗：加了两段内容后，1280×720 的笔记本上
  **「确认立项」点不到，表单填完提交不了**。

**怎么避免**：`max-h-[90vh] flex flex-col`，正文 `overflow-y-auto flex-1`，
按钮那一条 `shrink-0`。**永远不要赌高度**。

### 13. 新增筛选，就多一条「新建的东西被藏起来」的路径

**症状**（踩过三次）：「点了确认立项，没有任何反应」——
项目其实建好了，被默认筛选挡住了。第一次是范围、第二次是类别、第三次是工作台焦点。

**真因**：筛选是一个个加上去的，每加一个就多一条藏东西的路径。

**怎么避免**：
- 立项后**把每一个筛选都放开到最大**，而不是"切到它所属的那一档"
  （切档依赖"我算得对"，而我算错过）
- `tests/project-category.test.js` 里有一条测试会解析出所有参与列表过滤的
  `useState`，逐个核对立项后有没有重置 —— 新增筛选忘了处理时它会失败

### 14. 默认值每收紧一档，就多一条「东西在库里、人却看不见」的路径

而人看不见的第一反应不是「我筛错了」，是「系统坏了」。
**默认全开，收窄由用的人自己来。**

唯一的例外是「与我相关」（用户点名要的），
所以配了一句兜底提示：我的是 0、公司的不是 0 时直接说出来并给按钮。

### 15. 覆盖状态默认值的 `useEffect`

**症状**：把 `viewScope` 默认值改成 `'related'`，界面纹丝不动。

**真因**：另一处 `useEffect(() => setViewScope(...), [activeRole])` 在挂载时又推回去了。
它离筛选条很远，改筛选时根本不会看到。

**怎么避免**：改默认值时 `grep` 一遍这个 setter 的所有调用点。

### 16. 定义了从来没调用的组件

**症状**：`getCategoryBadge` 定义了但**一次都没被调用** ——
也就是说项目列表上一直看不出项目属于哪一类。
「分类」这件事反复讲不清，有一半原因是它压根没显示出来过。

**怎么避免**：加了展示用的函数，确认它真的被渲染。
`tests/project-category.test.js` 里现在数调用次数。

## 四、部署与运维

### 17. 直接改服务器的东西，活不过下一次部署

**症状**：2026-09-07 晚上在服务器上改 nginx 加了扫描器防护，
第二天一部署全被冲掉 —— 而部署自检只看首页 200，什么都没报。

**怎么避免**：
- 配置改动一律进仓库（`deploy/nginx-xinyi.conf`）
- 自检加上会说话的检查（现在部署最后会打印「扫描器防护 已生效 / ⚠️ 失效」）

### 18. 宽泛的匹配模式会打到你没想打的东西

**症状**（同一天两次）：
- `pkill -f "server/app.js"` 把用户**另一个项目**的开发服务器一起杀了（文件名一样）
- nginx 规则里写了裸的 `/vendor/`，把本站自己的
  tailwind/xlsx/pdf/mammoth 全掐成 444，**生产挂了 38 分钟，当时有人在用**

**真因**：宽泛模式的危害不对称。少匹配了只是没生效，会发现；
多匹配了是**静默地打坏别的东西**，而且往往打的是本来好好的那部分。

**怎么避免**：用模式做破坏性操作前，先跑一遍「它会命中什么」并逐条看 ——
`pgrep -af` 看清再用 PID；nginx 规则先在真实目录 `find` 一遍。

### 19. 只验「新功能生效」，不验「原本正常的还正常」

上面 18 的第二条就是这么漏的：我测了扫描器路径被挡住，
没测本站资源还能不能下载。**两边都要验。**

### 20. rsync `--delete` 会删掉服务器上「本地没有」的东西

**症状**：每次部署都在删服务器备份，一个 29.7MB 的备份就这么没的，全程无提示。

**怎么避免**：`deploy.sh` 里 `backups`、`.env.local`、`.runtime` 都在 exclude 列表里。
往那个列表里加东西前想清楚。

### 21. 腾讯云「异常登录」高危告警，多半是自己人

**症状**：一堆「异常登录」高危短信。

**真因**：部署密钥从境外出口 IP 登录，腾讯按地域判高危。
指纹 `SHA256:9iWRUJnDna/qjq3W9Wa7zOO4QWEyPyEiF2ifmn8ECgg` = 本机 `~/.ssh/id_ed25519_xinyi`。

**怎么避免**：**先比对 auth.log 里 `Accepted` 那行的公钥指纹**，指纹一致就是自己人。
指纹对不上才按入侵处置。「攻击检测」低危则是互联网背景扫描，打的全是 PHP 漏洞 —— 本机没有 PHP。

## 五、AI / 提醒 / 自动化

### 22. 提醒不许顺手建项目

**症状**：线上莫名其妙多出 15 个「跟进项目」，把在制项目数、
延误率、日志覆盖率的分母全污染了。

**真因**：`addReminder` 在 `linkType` 是 lead/customer 时，
会**先建一个项目**把提醒挂上去；建不成就 `return` —— 提醒被静默丢掉。
而提醒模型本来就支持挂在线索/客户上，铃铛也早就能跳过去，这个绕路从没必要。

**怎么避免**：提醒就是提醒。要给线索/客户排跟进，用 `scheduleRenewalFollowUp()`。

### 23. 改分类字段时，最容易漏的是「连带」

**症状**：把情报项目的类别从 FollowUp 改成 Public，
「转为线索」按钮**直接消失** —— 因为它的开关是 `isIntelOrigin && isFollowUpProject`。
不报错，只是按钮不见了，链路悄悄断掉。

**怎么避免**：改枚举值前 `grep` 这个值的所有使用点，
特别注意用它做**开关**的地方。

### 24. 加枚举值时，`=== 'Pending'` 这种写法会漏

**症状**：加了 `InProgress` 之后，
原来写 `status === 'Pending'` 当「未完成」用的地方，
**正在做的任务从这些判断里消失了** —— 结项时不提示、AI 不接手，都不报错。

**怎么避免**：加枚举值前 `grep` 一遍旧值，
判断「未完成」用 `!== 'Completed'` 这种否定式，而不是列举肯定式。

### 25. 写失败曾经是静默的

**症状**：顾问建项目返回 403，界面只 `console.warn`，看起来像成功了。

**怎么避免**：`AppContext` 里所有写操作的 `.catch` 走 `reportWriteFailure`，
失败一律回滚 + 顶部横幅说明。**不要新增静默的 catch。**

### 26. 自己写的注释会把解析器带偏

**症状**：`loadCapabilities()` 从 `constants.ts` 正则解析动作码，
把我注释里写的 `'OWN'` 当成了 CONSULTANT 的一个动作码。

**怎么避免**：解析源码前先剥注释。测试里也一样 ——
`tests/help-three-tier.test.js` 检查「代码里不许用 offsetParent」时，
必须先剥注释，否则那段讲这个坑的注释会让测试失败。

### 27. 拿正则剥 TypeScript 类型标注

**症状**：测试报 `Unexpected token ':'`，指不到真正的原因。

**真因**：正则遇到 `Record<...>` 和默认参数就把代码剥坏了。

**怎么避免**：项目里有 esbuild（`npm run build:metrics` 在用），
测试要加载纯逻辑的 TS 模块就用它转译，见 `tests/task-flow.test.js`。

## 六、业务规则（这些不是技术问题，是这家公司的事实）

### 28. 体系文件大部分可复用

金恩来 2026-09-08：「编写体系文件只要几个小时，同行业做过的
大部分可复用，改一下抬头和部分数据。」

**别拿它当耗时任务举例，也别按它估交付周期。**
这条还有个设计含义：知识中心最值钱的检索目标是
「上一次同行业做过什么」，比存标准条文原文有用得多。

### 29. 涉及行业工时和流程的判断，先问，不要推演

我编过一个「编写体系文件 200 小时」的例子，被当场纠正。
这个行业的实际节奏只有他们知道。

### 30. 老合同不生成项目

导入历史合同那条路**故意不建项目**：老合同早就做完了，
给每份都建一个项目等于往「在制项目」里塞一堆永远做不完的僵尸，
之后所有交付指标都不准了。
