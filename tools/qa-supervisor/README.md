# QA 协作监督台

本机监督 Claude 与 Codex 的上线巡检协作。它只读取：

- `docs/协作日志.md`：双方给老板看的交接流水；
- `.runtime/codex-logs/latest.log`：Codex 当前或最近一次执行现场；
- `docs/逐页清点报告.md` 与 `docs/可点元素清单.md`：测试进度。

运行：

```bash
npm run qa:supervisor
```

浏览器打开 `http://127.0.0.1:4176`。服务只监听本机，不上传日志，不调用模型，打开和刷新面板本身不消耗 Token。

## 布置任务

1. 点顶部“布置任务”或左侧“任务中心”。
2. 填任务名称、负责人、范围、具体操作和验收标准。
3. 默认不勾“立即启动负责人”：任务只进入本地任务板，不消耗模型 Token。
4. 确认内容后，勾选“立即启动负责人”再提交：Claude 或 Codex 会在后台开始执行。

建议把需要判断、改代码和安排复测的任务交给 Claude；把界面巡检、数据对账、脚本和报告交给 Codex。

## Token 控制规则

1. 日常派单只传任务、角色、页面、验收条件、证据路径。
2. Codex 回传结论、复现步骤和证据路径，不把完整终端日志交给 Claude。
3. 完整日志只在双方结论冲突时按需读取。
4. 截图保存在本机，模型只读取与争议点有关的图片。

协作额外消耗主要来自 Claude 对 Codex 结果的复核。按上述规则，目标增量是原单代理任务的 10%–25%；复杂争议和双方阅读全文会超过这个范围。
